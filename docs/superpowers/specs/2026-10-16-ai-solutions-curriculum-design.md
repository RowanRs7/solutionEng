# AI 解决方案架构师自学课程设计

## 1. 项目目标

本项目建设一套面向 AI 解决方案架构师的中文自学课程。课程服务于会少量 Python、但缺乏后端工程和系统集成经验的学习者，帮助他们从业务需求出发，理解传统解决方案和 AI 解决方案的完整生命周期。

课程以 Markdown 教材为主体，以短代码、可复现实验、技术图和测验为辅助。课程不是重代码项目，也不要求教师讲解。学习者应能独立阅读、操作、检查结果并定位常见问题。

当前范围只包含两个模块：

1. 传统解决方案知识体系。
2. AI 解决方案知识体系。

企业 AI 集成平台综合实战不属于当前版本。

## 2. 学习者与学习成果

### 2.1 学习者基础

学习者能够阅读和修改简单的 Python 或 JavaScript 代码，但不熟悉后端开发、企业身份、数据集成、部署和 AI 工程。

### 2.2 目标角色

课程面向 AI 解决方案架构师。课程兼顾业务分析、架构设计、系统集成、AI 选型、安全、交付和运维，不把学习者限定为单一应用开发工程师。

### 2.3 学习成果

完成课程后，学习者应能：

- 调研业务现状，定义系统边界、约束和验收标准。
- 解释并选择常见 Web、API、身份、数据和异步集成技术。
- 设计 SSO、JWT、Webhook、ETL、消息队列和权限方案。
- 识别适合 AI 的业务问题，选择模型、RAG、Workflow 或 Agent。
- 设计 AI 评测、安全、治理、成本和生产运维方案。
- 阅读常见技术架构，输出需求、接口、数据流、ADR、风险和运维文档。

## 3. 课程组织原则

课程以**解决方案生命周期**为主线，以**分层能力树**组织每个阶段的内部内容。

两个模块各自完整走过以下生命周期：

1. 发现需求。
2. 定义需求。
3. 设计方案。
4. 开发与集成。
5. 测试与验证。
6. 部署与交付。
7. 运行与优化。

每个主题按照六个认知层次展开：

1. **认识层**：它是什么，解决什么问题。
2. **理解层**：核心术语、组成和工作原理。
3. **设计层**：适用场景、选型方法和主要权衡。
4. **应用层**：用小型 Python 或 FastAPI 示例验证机制。
5. **诊断层**：识别故障、安全风险和排查路径。
6. **架构层**：把该能力与其他组件组合成完整方案。

知识条目分为三类：

- `core`：核心课程，要求理解并完成练习。
- `card`：技术卡片，用较短篇幅解释高频概念。
- `advanced`：扩展专题，说明用途、边界和继续学习路径。

预计总学习时间为 60 至 80 小时。传统解决方案模块约 30 小时，AI 解决方案模块约 24 小时；导读、复习、测验和扩展阅读占用剩余时间。完整知识地图覆盖全部条目，但不同条目不平均分配课时。

## 5. 模块一：传统解决方案知识体系

模块一包含 67 个候选课程条目。实施计划将按内容密度把它们拆分或合并为核心课程、技术卡片和扩展专题，同时保持本节列出的知识覆盖范围。

### 5.1 需求发现与定义

- 解决方案架构师的工作。
- 利益相关者与业务目标。
- 现状调研与业务流程。
- 用户、角色、场景与用例。
- 功能需求与非功能需求。
- 系统边界、约束、依赖与假设。
- 优先级、范围与验收标准。
- 风险识别和需求交付物。

### 5.2 Web 与网络基础

- 客户端、服务端和网络分层。
- TCP/IP、IP、端口、DNS、路由和防火墙。
- HTTP 请求、响应、方法和状态码。
- Header、Cookie、缓存和内容协商。
- HTTPS、TLS、证书和加密基础。
- JSON、XML、CSV、编码和序列化。
- CORS、CSRF 和浏览器安全。
- `curl`、网络诊断和抓包思路。
- 反向代理、负载均衡和 CDN。

### 5.3 API 与系统集成

- API、REST 和资源建模。
- OpenAPI 与接口契约。
- 参数校验、统一错误模型和版本管理。
- 分页、过滤、批量操作与限流。
- 超时、重试、退避、幂等、熔断、降级和隔离。
- Webhook 的设计、签名和重放保护。
- 轮询、SSE、WebSocket 和回调。
- 邮件、短信、定时任务、文件交换与 SFTP。
- 消息队列、发布订阅、事件流和死信队列。
- Outbox、补偿操作和最终一致性。
- ETL、ELT、CDC 和数据同步。
- 同步与异步集成模式选型。

### 5.4 身份、权限与安全

- 身份认证、授权和审计。
- 密码哈希、MFA、Session、Cookie 和 API Key。
- JWT 的结构、签发、校验、刷新和吊销。
- OAuth 2.0 的角色、授权流程和 PKCE。
- OpenID Connect 和身份令牌。
- SSO、SAML 和企业身份接入。
- RBAC、ABAC、最小权限和多租户权限。
- Secret、证书和密钥管理。
- 常见 Web/API 攻击与安全设计。
- 数据分类、加密、脱敏、审计和合规基础。

### 5.5 数据与应用架构

- SQL、表设计和数据关系。
- 索引、事务、锁、连接池和数据库迁移。
- NoSQL、Redis、缓存和缓存失效策略。
- 对象存储和文件管理。
- 时间、时区、金额、UUID、空值、字符编码与精度。
- 数据质量、校验、去重和一致性。
- 单体、模块化单体、微服务和无服务器架构。
- 反向代理、API Gateway 和服务发现。
- 高可用、扩展、容错、备份和灾难恢复。
- 架构权衡、ADR、容量与成本估算。

### 5.6 开发、测试与交付

- FastAPI 最小服务和项目分层。
- 依赖、虚拟环境、配置和 Secret。
- 异常处理、统一错误与结构化日志。
- Git、分支、语义化版本和代码审查。
- 单元、集成、契约、端到端和用户验收测试。
- 性能、安全和数据质量测试。
- Linux、进程和常用诊断方法。
- Docker 和 Docker Compose。
- CI/CD、数据库变更、灰度发布和回滚。
- 云计算、Kubernetes 和 IaC 概览。

### 5.7 运行与持续优化

- 日志、指标、Tracing 和告警。
- Correlation ID 和请求链路。
- OpenTelemetry、Prometheus 和 Grafana 的作用。
- SLI、SLO、SLA 和错误预算。
- 性能、容量、配额和成本管理。
- 故障分级、排查、应急响应和复盘。
- 备份、恢复和业务连续性。
- Runbook、运维手册和知识移交。

## 8. 重点标记与结构化表达

教材统一使用以下语义样式：

- **粗体**标记核心概念、结论和必须记住的规则。
- *斜体*标记首次出现的术语、语义强调和补充说明。
- <u>下划线</u>标记容易误用、需要重点复习或必须警惕的内容。
- **<u>粗体加下划线</u>**标记安全风险和生产事故风险。
- `行内代码`标记命令、参数、字段、函数、文件名和协议值。
- 引用块承载核心结论、提示、注意、最佳实践和常见误区。

下划线通过内嵌 HTML `<u>` 实现。每个段落只表达一个主题，列表中的并列项采用一致句式。表格用于比较，步骤列表用于操作，决策清单用于选型。样式服务于理解，不把整段文字全部加粗或加下划线。

示例：

> **核心结论：** JWT 默认只是编码和签名，*不是加密*。  
> **<u>不要在 JWT Payload 中存放密码、密钥或其他敏感明文。</u>**

## 9. 代码与实验规范

代码只承担解释和验证作用。第一模块使用 Python 3、FastAPI、HTTP 客户端和少量 Docker Compose；第二模块通过统一 AI Provider 接口降低厂商绑定。

每个代码示例按以下顺序呈现：

1. 说明待解决问题。
2. 列出运行环境、输入和输出。
3. 提供带逐行注释的完整代码。
4. 按模块解释整体执行流程。
5. 解释关键设计选择。
6. 给出运行命令和预期结果。
7. 分析常见错误、安全风险和改进方向。

教学代码的每一行都应说明其目的。注释解释设计意图、数据流或框架行为，避免只把语法翻译成中文。长代码按职责拆成小段讲解，并提供可直接运行的完整版本。

JSON 等不支持注释的格式必须保持合法。教材在代码块下逐字段解释，不能为了逐行注释而提供无法执行的伪代码。命令、配置和输出也需要说明关键行的意义。

每个实验必须：

- 说明前置条件和依赖。
- 提供输入、操作步骤和预期输出。
- 提供验证方法和清理方法。
- 为需要付费 API 或密钥的实验提供 Mock 或离线替代方案。
- 禁止硬编码真实凭据和个人信息。
- 说明失败症状、原因、验证方法和修复方向。

## 10. 测验与自学反馈

每篇核心课程包含 3 至 5 道概念题、1 道场景判断题和 1 个可选动手任务。答案解释正确选项，也解释错误选项错在哪里。

每个生命周期阶段包含一次综合检查：

- 知识检查清单。
- 场景分析题。
- 架构师交付物练习。
- 自我评分标准。
- 薄弱知识回看链接。

主观题必须提供参考思路和评价量表，使学习者不依赖教师批改也能判断完成质量。

- 适用和不适用场景明确。
- 示例能够独立运行。
- 核心代码逐行注释，并有整体流程说明。
- 命令、输出和故障现象经过验证。
- 生产风险和安全边界明确。
- 前置课程、相关课程和下一课链接正确。
- 测验覆盖学习目标，并提供答案解析。
- 外部链接有效，时效性内容标明复核日期。
- 粗体、斜体、下划线和警告样式符合语义规范。

仓库级检查覆盖 Markdown 格式、内部链接、重复标题、Front Matter、代码块语法和可运行示例。涉及模型接口、框架、MCP、安全清单和供应商能力的内容变化较快，必须与稳定原理分开表达，并按 `last_reviewed` 定期复核。

## 13. 内容生产顺序

内容按六个批次实施：

1. 建立课程入口、知识地图、术语表、模板和自动检查。
2. 编写第一模块核心课程。
3. 补充第一模块技术卡片和扩展专题。
4. 编写第二模块核心课程。
5. 补充第二模块技术卡片和扩展专题。
6. 完善阶段测验、索引、交叉引用和全局质量检查。

每个批次先确定精确文件清单和验收条件，再编写正文。每完成一个生命周期阶段，就执行格式、链接、代码和内容复核，避免把问题累积到课程末尾。

## 14. 当前版本不包含的内容

当前版本不设计或实现企业 AI 集成平台综合实战，也不建设视频、教师讲义、学习管理系统、自动评分平台或双语言版本。这些内容可在前两个知识模块稳定后另行设计。
