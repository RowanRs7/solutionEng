# 开发、测试与交付

## 单元目标

上一单元把退款方案画在了图纸上，这一单元开始“施工”：把设计变成能跑、能测、能反复上线的服务。

可以把它想成装修一套房子：先分好房间（分层），再把水电煤气接对（依赖与配置），装好总闸和报警器（异常与日志），施工过程留图纸和验收单（分支与评审、测试），最后打包发运、按房间逐个交付（镜像、CI/CD、Kubernetes）。每道工序都不难，难的是**知道下一步该做什么、做错了在哪一步能发现**。

本单元就是按这个顺序走的：用 FastAPI 写出分层服务，把配置与密钥管住，用异常处理和结构化日志让故障可定位，用分支与测试分层建立质量闸门，最后借助 Docker、CI/CD 与 Kubernetes 把变更安全送上生产，并在出问题时灰度回滚。学完你能独立搭起一条从提交到上线的交付链路，并为每一次拒绝、回滚和排障提供可复核的证据。

## 学习路线

预计学习时间 **9–11 小时**。课程按以下顺序学习（箭头表示依赖关系，前一篇没弄懂就别急着往后跳）：

1. [FastAPI 最小服务与项目分层](01-fastapi-service-and-layering.md)：先让服务跑起来，再把目录与职责分开。
2. [依赖、虚拟环境、配置与 Secret](02-dependencies-config-and-secrets.md)：环境可复现，密钥不进代码与日志。
3. [异常处理与结构化日志](03-exception-handling-and-structured-logging.md)：让一次失败请求能在日志里被定位。
4. [Git、版本与代码审查](04-git-branching-and-code-review.md)：改动可追溯、可回滚、可评审。
5. [单元、集成、契约、端到端与验收测试](05-test-levels-and-acceptance.md)：每一层测什么，测到什么程度算验收。
6. [性能、安全与数据质量测试](06-performance-security-and-data-testing.md)：把非功能要求变成发布前的闸门。
7. [Linux、进程与诊断方法](07-linux-processes-and-diagnostics.md)：线上排障的第一手工具与观察顺序。
8. [Docker 与 Docker Compose](08-docker-and-compose.md)：把运行环境打进镜像，在本地复现依赖。
9. [CI/CD、变更、灰度与回滚](09-cicd-migrations-canary-and-rollback.md)：让每次发布都能安全撤回。
10. [云计算、Kubernetes 与 IaC](10-cloud-kubernetes-and-iac.md)：让环境随时可以重建。
11. [开发、测试与交付阶段综合测评](11-stage-assessment.md)：检验本单元的掌握程度。

如果时间紧，可以按“三段式”分配：**第 1–3 课**先把服务立起来并能查问题；**第 4–6 课**把质量闸门补齐；**第 7–10 课**再学怎么打包、发布和托底。测评留到最后，不要边学边做。

## 贯穿场景

晴空商城的退款方案在前一单元已经设计成型，到了本单元就要真正跑起来：退款接口怎样分层、支付密钥从哪里读、一次失败请求怎样在日志里被一眼定位、改动由谁审查、测试覆盖到哪一层才算验收、压测与安全扫描如何不拖慢发布、镜像与 Compose 怎样复现环境、数据库迁移和灰度发布如何避免退款被重复扣款、Kubernetes 与 IaC 又怎样让环境随时可重建。每一课补上退款链路的一个工程侧面，合起来才是一条可交付、可回滚的链路。

> **读法提示：** 每篇核心课都按“为什么 → 概念 → 原理 → 示例 → 实验 → 排错 → 安全 → 练习”推进。第一遍可以只读概念和示例，动手实验一定要做；做完实验再回头读原理，会顺畅很多。

## 必交成果

- 可运行的 FastAPI 服务骨架，含分层目录与配置注入。
- 异常处理与结构化日志清单，能定位一次具体的失败请求。
- 测试方案：单元、集成、契约与端到端各层的用例和验收标准。
- Dockerfile 与 Compose 编排文件，可在本地一键启动依赖。
- CI/CD 流水线配置，含迁移、灰度与回滚步骤说明。
- 阶段测评答卷与复盘记录。

## 完成规则

先完成全部课程与练习，再做阶段测评。测评达到 **80 分**视为掌握；60–79 分按复习路线补课，重点回看失分课程；低于 60 分重做核心练习后再测。
