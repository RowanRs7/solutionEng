# Web 与网络阶段综合测评

## 学习目标

本测评检验能否把九课的机制串成一条可验证的链路：从域名解析、建连、TLS、HTTP 语义、头部与缓存、跨源安全，到入口代理与 CDN，并用 curl 的分段数据把猜测变成结论。建议闭卷完成概念题，场景与交付物可查课程，最后按评分表自评。

## 知识检查清单

- [ ] 能用“往返次数 × RTT + 字节数 ÷ 带宽 + 服务端处理 + 渲染”拆解页面耗时，并指出最大加数。
- [ ] 能写出一次调用的五段路径：名字 → 地址 → 路由 → 放行 → 握手，并区分 `refused` 与 `timed out`。
- [ ] 能说明方法的安全性与幂等性，并用 201、202、409、429 表达不同结果。
- [ ] 能区分 `max-age`、`s-maxage`、`private`、`no-store`、`no-cache`，并说清 `Vary` 的作用。
- [ ] 能写出一条登录 Cookie 的 `HttpOnly`、`Secure`、`SameSite` 组合，并说明各挡什么。
- [ ] 能说明 TLS 握手的三件事、证书的五步校验，以及证书、公钥、私钥、会话密钥的关系。
- [ ] 能为 JSON 金额、订单号前导零和 CSV 公式注入给出防错约定。
- [ ] 能判断同源、简单请求与预检，并说明 CORS 为什么挡不住 CSRF。
- [ ] 能用 `curl -w` 的五段差值定位慢在哪一层，并按退出码分诊。
- [ ] 能说明反向代理、负载均衡、CDN 三个决策点，以及会话保持与健康检查的边界。

## 概念题

共 40 分：第 1–12 题单选，每题 2 分；第 13–16 题简答，每题 4 分。请写出依据，而不是只写字母。

1. 【第 1 课·分层与耗时】首屏 4 秒，RTT 约 180 ms，资源 1.2 MB，链路 20 Mbps。最该先补的数据是？
   A. 带宽余量　B. 首字节时间与请求数　C. 客户端内存　D. 服务端 CPU 型号
2. 【第 2 课·DNS】域名已改到新 IP，两天后仍有少量请求打到旧地址。最先查什么？
   A. 证书 SAN　B. 客户端 hosts 与本地 DNS 缓存　C. 安全组规则　D. CORS 白名单
3. 【第 2 课·防火墙】客户端报 `connection timed out`，服务端没有任何请求日志。最可能的是？
   A. 端口没有进程监听　B. 安全组静默丢弃报文　C. 证书链不完整　D. 方法不被支持
4. 【第 3 课·方法与幂等】下列哪组方法都幂等？
   A. GET、POST　B. PUT、DELETE　C. POST、PATCH　D. GET、POST、PATCH
5. 【第 3 课·状态码】前台要求 2 秒出结果，供应商 P99 是 90 秒。最合适的表达是？
   A. 同步等待后返回 201　B. 立即返回 202、`Location` 与幂等键　C. 超时后返回 200　D. 返回 302 让前端轮询
6. 【第 4 课·缓存边界】客服退款详情页含会员手机号。哪个响应头组合最合适？
   A. `public, s-maxage=600`　B. `private, no-store`　C. `ETag` 加一年 `max-age`　D. 只写 `Vary: Accept-Encoding`
7. 【第 4 课·缓存语义】`Cache-Control: no-cache` 的含义是？
   A. 不得存储　B. 可以存储，但每次使用前必须验证　C. 只对 CDN 生效　D. 与 `no-store` 等价
8. 【第 5 课·TLS】握手结束后，加密 HTTP 报文使用的是？
   A. 服务端私钥　B. 证书里的公钥　C. 本次协商出的对称会话密钥　D. 根证书公钥
9. 【第 5 课·证书链】只部署叶证书、漏发中间证书，客户端最可能报？
   A. 域名不匹配　B. 无法构建到受信任根的链　C. 私钥泄露　D. 证书用途不符
10. 【第 6 课·类型与精度】金额 19.90 以 JSON 数字传输，主要风险是？
    A. 体积过大　B. 双精度浮点带来精度丢失　C. 不能跨语言解析　D. 无法被压缩
11. 【第 7 课·CORS】下列说法正确的是？
    A. 配好 CORS 白名单即可替代 CSRF 防御　B. 所有跨源请求都先发预检　C. 简单请求会真实发出，浏览器只是不把响应交给脚本　D. 预检会携带用户 Cookie
12. 【第 8 课·curl 分段】`time_namelookup=0.05`、`time_connect=0.25`、`time_appconnect=0.55`（秒）。TCP 与 TLS 各约多久？
    A. 0.25 / 0.30　B. 0.20 / 0.30　C. 0.20 / 0.55　D. 0.05 / 0.30
13. 【第 1 课·延迟与带宽】用一句话区分 RTT 与带宽，并说明它们各自决定总耗时的哪一项。
14. 【第 3 课·状态码语义】说明 401 与 403、404 与 405 的差别，并各给一个订单或退款场景的例子。
15. 【第 7 课·浏览器安全】为什么“接口已配 CORS 白名单”不能作为写操作的防伪措施？
16. 【第 5 课·TLS 责任】TLS 终止位置放在 CDN 还是源站，会影响哪三件事？各举一条。

## 常见错答分析

| 高频误解 | 为什么错 | 正确理解 |
| --- | --- | --- |
| “HTTPS 就是把内容加密，私钥在证书里，所以谁拿到证书谁就能解密。” | 混淆了证书、公钥与对称密钥的职责；私钥从不下发给客户端。 | 证书只绑定域名与公钥，用于握手验身；应用数据由双方临时协商的对称密钥加密。 |
| “退款接口已限制 CORS 来源，别的站点就伪造不了请求。” | CORS 管的是浏览器是否把响应交给脚本，不管请求能否发出；非浏览器客户端根本不看它。 | 写操作要靠认证、CSRF Token、`SameSite` 与来源校验；CORS 只是读取侧的受控豁免。 |
| “CDN 命中率低，把所有响应都改成缓存一天即可。” | 长缓存会让含个人信息或库存价格的响应被共享，发版后也无法及时更新。 | 按内容分层：静态指纹资源长缓存，HTML 用 `no-cache` 加 `ETag`，含个人信息强制 `private` 或 `no-store`。 |

## 场景分析

云岭滑雪场要上线“雪票预订 + 闸机核销”平台。它与晴空商城的退款链路不同，约束如下：

- 预订页主要在微信内置浏览器打开，登录态放在 `qingkong.example` 父域 Cookie 上；合作方“雪具租赁”在页面里嵌入脚本，需要读取余票接口。
- 票价与余票九成来自未登录浏览，价格 5 分钟变一次；会员价与“我的订单”必须按人返回。
- 闸机在雪场本地，只有一条 4G 备份链路，断网时仍需核销已入场订单。
- 支付回调由第三方发起，对方要求固定出口 IP 白名单与 TLS 1.2 以上，且可能重复推送。
- 周末 7:00–9:00 是峰值，运维要求“进程活着但不响应”的实例在 10 秒内停止接流量。

请回答：

1. 给票价页、会员价、我的订单、支付回调四类请求各写一条缓存结论（能否进共享缓存、关键响应头、缓存键是否含 Cookie 或用 `Vary`）。
2. 微信内登录态与雪具租赁脚本同时存在时，`SameSite`、CORS 白名单、CSRF Token 三者各要满足什么？哪一项最容易被配错？
3. 闸机在 4G 链路上偶发核销超时并出现重复核销。请写出根因假设、用 curl 的哪个分段指标验证哪一段，以及业务侧的最小防重设计。
4. 支付回调要穿过 CDN、反向代理再到订单服务（3 副本）。它该不该被缓存、该不该做会话保持？跨副本的重复通知靠什么保证不出错？

## 架构师交付物练习

产出一份《雪票平台接入与链路设计说明书》，用五张表交付，每张表都要能被评审会当场追问：

1. **入口与证书表**：域名、用途、TLS 终止层、证书责任人与续期方式、临期告警阈值。
2. **缓存矩阵**：路径、是否可共享、`Cache-Control`、缓存键含哪些维度、失效或预热方式。
3. **跨源与凭据表**：来源、目标接口、是否带凭据、允许的方法与头、CSRF 防护手段。
4. **故障分诊表**：症状、最可能所在层、一条验证命令、判定阈值、升级对象。
5. **上线检查清单**：至少 8 条勾选项，覆盖 DNS TTL、证书链、`Vary`、`X-Forwarded-For`、健康检查与回滚。

提示：每行只写一个可验证的决定；不确定的数字标“待测”，并写明由谁在何时给出。

## 参考答案与解析

### 概念题答案

1. B。先分清 4 秒里往返、字节、服务端与渲染各占多少；只升级带宽可能改不动最大加数。
2. B。TTL 到期不等于所有缓存都清空，容器 `hosts` 与本地缓存常写死旧地址。
3. B。静默丢弃才会表现为超时，且无日志说明包未到进程；端口无监听应报 `refused`。
4. B。GET、PUT、DELETE 幂等；POST 通常不幂等，PATCH 视实现而定。
5. B。用 202 与 `Location` 表达“已受理”，用幂等键保证重复点击只退一次。
6. B。含个人信息不得进入共享缓存：`private` 挡住 CDN，`no-store` 挡住落盘。
7. B。`no-cache` 允许存储但必须回源验证；禁止存储是 `no-store`。
8. C。证书只用于验身与协商，真正加密数据的是对称会话密钥。
9. B。缺中间证书导致链断裂，与域名是否匹配无关。
10. B。JSON 数字无精度规定，金额宜用字符串或最小货币单位的整数。
11. C。CORS 是读取侧的受控豁免；简单请求照样执行，预检也不带 Cookie。
12. B。TCP 为 0.25 − 0.05，TLS 为 0.55 − 0.25；累计值必须相减才是单段耗时。
13. RTT 决定“多久开始”（往返次数乘以它），带宽决定“多久传完”（字节数除以它），两者要用不同手段优化。
14. 401 是未认证、403 是已认证但无权限；404 是资源不存在、405 是资源存在但不支持该方法且须带 `Allow`。例：未带令牌查订单返回 401，客服查他人订单返回 403，对退款资源用 `DELETE` 返回 405。
15. CORS 只约束浏览器是否把响应交给脚本，不阻止请求发出；攻击者可用表单或脚本直连，服务端也无法凭 `Origin` 判定请求可信。写操作需认证、Token、`SameSite` 与来源校验共同成立。
16. 影响信任边界（源站能否被绕过）、证书责任（谁续期、谁在短时间内发现临期）与故障归属（握手失败该找 CDN 还是源站团队）；也可提加密到源站带来的 CPU 与排障成本。

### 场景分析评分要点

- 第 1 问：票价与余票可共享，`s-maxage` 加 TTL 抖动，缓存键含路径与必要语言维度；会员价与订单必须 `private, no-store`，不能靠缓存键含 Cookie 来“分人”；支付回调 `no-store`。只写“加缓存”不给分。
- 第 2 问：`SameSite=None` 必须配 `Secure`，并意识到父域 Cookie 会被更多子域共享；CORS 白名单要精确回显、加 `Vary: Origin`，不可与 `*` 和凭据同用；写操作需与会话绑定的 Token。最易配错的是“用白名单替代 Token”或漏 `Vary: Origin`。
- 第 3 问：先假设抖动在建连、TLS 还是首字节段，用 `-w` 差值验证，再看退出码是 28 还是 6、7；重试复用同一幂等键，闸机侧先落本地核销记录再同步，以票号加设备序列号做唯一键。
- 第 4 问：回调是状态变更，不缓存、不做会话保持；重复通知由订单号幂等键与去重表吸收；监控回调失败率与被幂等拦下的重复次数。
- 常见错误：把“未登录浏览”等同于“所有内容都能缓存”；给闸机加无限重试；用会话保持解决重复通知；把回调失败包装成 200 掩盖问题。

### 交付物参考结构

| 表 | 参考内容 |
| --- | --- |
| 入口与证书 | 预订页在 CDN 终止、源站保留自身证书；写明证书责任人、自动续期、到期前 30/7/1 天告警。 |
| 缓存矩阵 | 静态资源指纹长缓存；票价页 `s-maxage=300` 加抖动；会员价与订单 `private, no-store`；回调 `no-store`。 |
| 跨源与凭据 | 精确来源、开启凭据、列出自定义 Token 头、`Vary: Origin`；写接口强制 Token。 |
| 故障分诊 | `timed out` 查安全组与路由；`refused` 查监听；握手错误查证书与协议；TTFB 高查服务端与上游。 |
| 上线清单 | 迁移前降 TTL、部署完整链、核对 `Vary`、确认 `X-Forwarded-For` 取值跳数、健康检查探业务就绪点、保留回滚。 |

合理答案可换技术与数字，但待测项必须标出责任人与期限，不能把建议写成已批准承诺。
