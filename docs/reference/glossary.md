# 术语表

| 术语 | 定义 |
| --- | --- |
| 解决方案 | 针对业务目标的一组技术、流程和交付安排。 |
| 解决方案架构 | 描述组件、边界、关系、约束和关键决策的设计。 |
| [利益相关者](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#利益相关者地图) | 受方案影响、能够影响方案或拥有关键信息的人或组织。 |
| [发起人](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#利益相关者地图) | 为项目提供方向、授权或资源的人。 |
| [业务目标](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#目标产出和成果) | 组织希望通过行动取得的结果。 |
| [产出](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#目标产出和成果) | 项目直接交付的产品、功能或文档。 |
| [成果](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#目标产出和成果) | 产出被使用后带来的可观察变化。 |
| [指标](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#目标产出和成果) | 用于判断目标或质量是否达成的可测量值。 |
| [关注点](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#关注点与冲突) | 利益相关者希望方案保护、改善或避免的事项。 |
| [决策所有者](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#利益相关者地图) | 对某类决定拥有最终授权的人。 |
| [解决方案架构师](../01-traditional-solutions/01-discovery-and-requirements/01-solution-architect-role.md#核心概念) | 连接业务目标与可交付方案，协调边界、决策、风险和技术关系的角色。 |
| [业务流程](../01-traditional-solutions/01-discovery-and-requirements/03-current-state-and-business-process.md#核心概念) | 为实现业务结果而发生的一组有顺序的活动、交接和例外。 |
| [现状证据](../01-traditional-solutions/01-discovery-and-requirements/03-current-state-and-business-process.md#核心概念) | 支持对当前系统、流程、等待或问题描述的可核验信息及其来源。 |
| [外部参与者](../01-traditional-solutions/01-discovery-and-requirements/04-users-roles-scenarios-and-use-cases.md#核心概念) | 位于系统边界外、与系统交互的人、组织角色或外部系统。 |
| [用例](../01-traditional-solutions/01-discovery-and-requirements/04-users-roles-scenarios-and-use-cases.md#核心概念) | 描述参与者为达成目标与系统交互的主流程、备选流程和结果。 |
| [场景](../01-traditional-solutions/01-discovery-and-requirements/04-users-roles-scenarios-and-use-cases.md#核心概念) | 描述特定角色在具体上下文中，为达成目标而采取行动及其结果。 |
| [功能需求](../01-traditional-solutions/01-discovery-and-requirements/05-functional-and-non-functional-requirements.md#核心概念) | 描述系统必须执行的行为。 |
| [非功能需求](../01-traditional-solutions/01-discovery-and-requirements/05-functional-and-non-functional-requirements.md#核心概念) | 描述系统行为必须满足的质量条件，通常需要具体化为可验证的质量属性。 |
| [质量属性](../01-traditional-solutions/01-discovery-and-requirements/05-functional-and-non-functional-requirements.md#核心概念) | 描述系统在特定条件下应达到的质量。 |
| [质量属性场景](../01-traditional-solutions/01-discovery-and-requirements/05-functional-and-non-functional-requirements.md#核心概念) | 用刺激源、刺激、环境、对象、响应和响应度量描述质量要求的结构。 |
| [可测量需求](../01-traditional-solutions/01-discovery-and-requirements/05-functional-and-non-functional-requirements.md#工作原理) | 明确条件、刺激、响应、阈值和验证方法，使团队能够判断需求是否达成。 |
| [系统边界](../01-traditional-solutions/01-discovery-and-requirements/06-boundaries-constraints-dependencies-assumptions.md#核心概念) | 本方案承诺设计、交付或改变的能力与责任范围。 |
| [约束](../01-traditional-solutions/01-discovery-and-requirements/06-boundaries-constraints-dependencies-assumptions.md#核心概念) | 限制方案选择或交付方式的已确认组织或技术条件。 |
| [依赖](../01-traditional-solutions/01-discovery-and-requirements/06-boundaries-constraints-dependencies-assumptions.md#核心概念) | 方案需要从其他人、系统、数据或决策取得输入或交付输出的关系。 |
| [上游与下游依赖](../01-traditional-solutions/01-discovery-and-requirements/06-boundaries-constraints-dependencies-assumptions.md#核心概念) | 相对本方案的数据或控制流方向；上游提供输入，下游接收输出或调用。 |
| [假设](../01-traditional-solutions/01-discovery-and-requirements/06-boundaries-constraints-dependencies-assumptions.md#核心概念) | 尚未验证、但当前方案暂时依赖的判断。 |
| [风险](../01-traditional-solutions/01-discovery-and-requirements/08-risks-and-requirement-deliverables.md#核心概念) | 未来不确定事件及其可能对目标造成的后果。 |
| [问题](../01-traditional-solutions/01-discovery-and-requirements/08-risks-and-requirement-deliverables.md#核心概念) | 已经发生并有证据、需要解决或跟踪的事件或缺陷。 |
| [风险触发条件](../01-traditional-solutions/01-discovery-and-requirements/08-risks-and-requirement-deliverables.md#核心概念) | 表明风险正在发生或需要启动响应的可观察信号。 |
| [风险所有者](../01-traditional-solutions/01-discovery-and-requirements/08-risks-and-requirement-deliverables.md#核心概念) | 负责跟踪风险、推动决策并确认应对措施完成的角色。 |
| [缓解措施](../01-traditional-solutions/01-discovery-and-requirements/08-risks-and-requirement-deliverables.md#核心概念) | 在风险发生前降低其发生概率或影响的行动。 |
| [应急方案](../01-traditional-solutions/01-discovery-and-requirements/08-risks-and-requirement-deliverables.md#核心概念) | 风险发生后限制损失或维持业务的预先安排。 |
| [残余风险](../01-traditional-solutions/01-discovery-and-requirements/08-risks-and-requirement-deliverables.md#核心概念) | 执行应对措施后仍然存在、需要评估和决定的风险部分。 |
| 交付物 | 生命周期某阶段产生并交给他人使用的结果。 |
| [验收标准](../01-traditional-solutions/01-discovery-and-requirements/07-priorities-scope-and-acceptance.md#核心概念) | 用于判断某项需求是否完成的可观察、可验证条件。 |
| [范围基线](../01-traditional-solutions/01-discovery-and-requirements/07-priorities-scope-and-acceptance.md#核心概念) | 经确认的首期范围、排除项、假设和验收条件版本，用作变更评估参照。 |
| [需求优先级](../01-traditional-solutions/01-discovery-and-requirements/07-priorities-scope-and-acceptance.md#核心概念) | 基于目标、风险、工作量、依赖和约束判断需求重要程度及顺序。 |
| [MoSCoW](../01-traditional-solutions/01-discovery-and-requirements/07-priorities-scope-and-acceptance.md#核心概念) | 用 Must、Should、Could 和 Won't this time 分类需求的范围讨论方法。 |
| [Given/When/Then](../01-traditional-solutions/01-discovery-and-requirements/07-priorities-scope-and-acceptance.md#核心概念) | 以给定条件、触发行为和可观察结果描述验收场景的格式。 |
| [需求追踪](../01-traditional-solutions/01-discovery-and-requirements/07-priorities-scope-and-acceptance.md#核心概念) | 将业务目标、需求、验收条件和验证证据关联起来的关系。 |
| [风险登记表](../01-traditional-solutions/01-discovery-and-requirements/08-risks-and-requirement-deliverables.md#核心概念) | 记录风险事件、概率/影响、触发、所有者、应对和状态的跟踪工具。 |
| [风险暴露](../01-traditional-solutions/01-discovery-and-requirements/08-risks-and-requirement-deliverables.md#核心概念) | 用概率和影响组合表示的相对关注程度，不是精确预测。 |
| [往返时延（RTT）](../01-traditional-solutions/02-web-and-network/01-web-architecture-and-layers.md#核心概念) | 一个报文从客户端到服务端再返回的时间，由距离、路由跳数与链路质量决定。 |
| [DNS](../01-traditional-solutions/02-web-and-network/02-tcp-ip-dns-and-firewall.md#核心概念) | 把域名解析成地址的分层、带缓存的分布式数据库。 |
| [幂等](../01-traditional-solutions/02-web-and-network/03-http-request-response.md#核心概念) | 同一请求执行一次和执行多次，服务端最终状态相同。 |
| [Cookie](../01-traditional-solutions/02-web-and-network/04-headers-cookies-and-caching.md#核心概念) | 服务端下发、浏览器保存并在同站请求中自动回传的键值对。 |
| [同源策略](../01-traditional-solutions/02-web-and-network/07-cors-csrf-and-browser-security.md#核心概念) | 浏览器限制一个源的文档读取另一个源响应、Cookie 与 DOM 的一组规则。 |
| [CORS](../01-traditional-solutions/02-web-and-network/07-cors-csrf-and-browser-security.md#核心概念) | 用响应头声明哪些源可以读取响应的协议，是同源策略的受控豁免。 |
| [反向代理](../01-traditional-solutions/02-web-and-network/09-reverse-proxy-load-balancer-cdn.md#核心概念) | 站在服务端一侧、代替后端接收客户端请求的代理。 |
| [CDN](../01-traditional-solutions/02-web-and-network/09-reverse-proxy-load-balancer-cdn.md#核心概念) | 把可共享的响应副本放到离用户最近边缘节点的分发网络。 |
| [REST](../01-traditional-solutions/03-api-and-integration/01-api-rest-and-resource-modeling.md#核心概念) | 以资源标识、通过表示操作资源、统一接口和无状态交互为核心的一组架构约束。 |
| [资源建模](../01-traditional-solutions/03-api-and-integration/01-api-rest-and-resource-modeling.md#核心概念) | 把业务用例拆解成资源、层级和行为的过程。 |
| [API 契约](../01-traditional-solutions/03-api-and-integration/01-api-rest-and-resource-modeling.md#核心概念) | 被固定下来供多方独立开发的调用约定，使调用方不读实现即可正确集成。 |
| [OpenAPI 文档](../01-traditional-solutions/03-api-and-integration/02-openapi-and-contracts.md#核心概念) | 描述 HTTP API 的标准格式，可用 YAML 或 JSON 书写。 |
| [限流](../01-traditional-solutions/03-api-and-integration/04-pagination-filtering-and-rate-limits.md#核心概念) | 限制单位时间内的请求次数，以保护服务端自身。 |
| [超时预算](../01-traditional-solutions/03-api-and-integration/05-timeout-retry-backoff-and-idempotency.md#核心概念) | 从对外承诺倒推出的可用时间，下游拿到的是剩余预算而非固定值。 |
| [指数退避](../01-traditional-solutions/03-api-and-integration/05-timeout-retry-backoff-and-idempotency.md#核心概念) | 让重试等待随次数翻倍，并叠加抖动把并发客户端打散的退避策略。 |
| [幂等键](../01-traditional-solutions/03-api-and-integration/05-timeout-retry-backoff-and-idempotency.md#核心概念) | 发起方为一次业务意图生成的稳定标识，服务端据此拦截重复与并发。 |
| [熔断器](../01-traditional-solutions/03-api-and-integration/06-circuit-breaking-degradation-and-isolation.md#核心概念) | 调用链上的状态开关，技术失败率超阈值即打开并快速返回。 |
| [死信队列](../01-traditional-solutions/03-api-and-integration/10-message-queues-pubsub-and-dlq.md#核心概念) | 存放重试耗尽、再也无法正常处理的消息的队列，是待人工处置的清单。 |
| [Outbox 表](../01-traditional-solutions/03-api-and-integration/11-outbox-compensation-and-eventual-consistency.md#核心概念) | 与业务表同库的事件暂存表，业务变更与待发事件写在同一个本地事务里。 |
| [补偿](../01-traditional-solutions/03-api-and-integration/11-outbox-compensation-and-eventual-consistency.md#核心概念) | 为已生效的步骤追加一个语义相反的新动作，而不是回滚。 |
| [最终一致性](../01-traditional-solutions/03-api-and-integration/11-outbox-compensation-and-eventual-consistency.md#核心概念) | 没有新写入时，系统经过有限时间会收敛到一致状态。 |
| [CDC](../01-traditional-solutions/03-api-and-integration/12-etl-elt-cdc-and-data-sync.md#核心概念) | 持续取得某一时刻之后每一条变更的数据捕获方式。 |
| [认证](../01-traditional-solutions/04-identity-and-security/01-authentication-authorization-and-audit.md#核心概念) | 验证主体声称的身份是否成立，失败时返回 401。 |
| [授权](../01-traditional-solutions/04-identity-and-security/01-authentication-authorization-and-audit.md#核心概念) | 在身份确定后判断主体能否对某个资源执行某个动作。 |
| [JWT](../01-traditional-solutions/04-identity-and-security/03-jwt-structure-and-validation.md#核心概念) | 把声明集合编码成用点分成头部、载荷与签名三段的字符串格式。 |
| [OAuth 2.0](../01-traditional-solutions/04-identity-and-security/04-oauth2-flows-and-pkce.md#核心概念) | 规定应用如何在不接触用户密码的前提下取得限定范围访问令牌的授权框架。 |
| [PKCE](../01-traditional-solutions/04-identity-and-security/04-oauth2-flows-and-pkce.md#核心概念) | 为授权码流程加一个只有发起方知道的高熵秘密的扩展。 |
| [OIDC](../01-traditional-solutions/04-identity-and-security/05-openid-connect-and-id-tokens.md#核心概念) | OAuth 2.0 之上的认证层，只多规定怎样把认证结果告诉客户端。 |
| [SAML 2.0](../01-traditional-solutions/04-identity-and-security/06-sso-saml-and-enterprise-identity.md#核心概念) | 基于 XML 的断言协议，IdP 用私钥签名断言并由浏览器带给 SP。 |
| [RBAC](../01-traditional-solutions/04-identity-and-security/07-rbac-abac-and-multi-tenant-permissions.md#核心概念) | 把权限授予角色、再把角色授予主体的访问控制模型。 |
| [ABAC](../01-traditional-solutions/04-identity-and-security/07-rbac-abac-and-multi-tenant-permissions.md#核心概念) | 把主体、资源、动作和环境属性一起送进策略求值的访问控制。 |
| [租户](../01-traditional-solutions/04-identity-and-security/07-rbac-abac-and-multi-tenant-permissions.md#核心概念) | 共享同一套系统但数据互不可见的一组主体。 |
| [信封加密](../01-traditional-solutions/04-identity-and-security/08-secrets-and-key-management.md#核心概念) | 用主密钥加密数据密钥、再用数据密钥加密内容的分层做法。 |
| [MVCC](../01-traditional-solutions/05-data-and-architecture/02-indexes-transactions-and-migrations.md#核心概念) | 让写产生新版本、读按快照取版本，从而使读不阻塞写的并发控制。 |
| [连接池](../01-traditional-solutions/05-data-and-architecture/02-indexes-transactions-and-migrations.md#核心概念) | 复用预建连接的资源管理方式，池大小就是并发上限。 |
| [缓存击穿](../01-traditional-solutions/05-data-and-architecture/03-nosql-redis-and-caching.md#核心概念) | 某个热点键恰好过期，瞬间大量并发同时回源把连接池打满。 |
| [缓存雪崩](../01-traditional-solutions/05-data-and-architecture/03-nosql-redis-and-caching.md#核心概念) | 大批键在同一时刻过期或缓存整体不可用，流量一次性压到数据库。 |
| [对象存储](../01-traditional-solutions/05-data-and-architecture/04-object-storage-and-file-management.md#核心概念) | 用 HTTP 存取不可变字节块的存储，写入即整个对象的替换。 |
| [预签名 URL](../01-traditional-solutions/05-data-and-architecture/04-object-storage-and-file-management.md#核心概念) | 服务端用密钥算出、带过期的授权链接，持有者可以签发者身份读写该对象。 |
| [API 网关](../01-traditional-solutions/05-data-and-architecture/08-api-gateway-and-service-discovery.md#核心概念) | 面向所有客户端的统一入口，按配置完成路由、鉴权、限流与改写。 |
| [服务发现](../01-traditional-solutions/05-data-and-architecture/08-api-gateway-and-service-discovery.md#核心概念) | 让调用方按服务名找目标的机制：登记自己、查出别人。 |
| [RTO](../01-traditional-solutions/05-data-and-architecture/09-high-availability-and-disaster-recovery.md#核心概念) | 从故障发生到业务恢复的最长时间。 |
| [RPO](../01-traditional-solutions/05-data-and-architecture/09-high-availability-and-disaster-recovery.md#核心概念) | 恢复后最多允许丢失多长时间的数据。 |
| [ADR](../01-traditional-solutions/05-data-and-architecture/10-architecture-tradeoffs-and-adr.md#核心概念) | 只讲一个决策的短记录，固定回答背景、选项、决定、后果并带状态。 |
| [依赖锁定](../01-traditional-solutions/06-build-test-deliver/02-dependencies-config-and-secrets.md#核心概念) | 把解析后的完整版本集合与校验和写进文件，使安装结果可复现。 |
| [结构化日志](../01-traditional-solutions/06-build-test-deliver/03-exception-handling-and-structured-logging.md#核心概念) | 每条记录都是固定字段键值对（通常一行 JSON）的日志。 |
| [语义化版本](../01-traditional-solutions/06-build-test-deliver/04-git-branching-and-code-review.md#核心概念) | 按主版本、次版本、修订号书写，用版本号承诺兼容性的规则。 |
| [测试金字塔](../01-traditional-solutions/06-build-test-deliver/05-test-levels-and-acceptance.md#核心概念) | 把测试层级按数量排成下宽上窄：大量单元、较少集成、个位数端到端。 |
| [灰度发布](../01-traditional-solutions/06-build-test-deliver/09-cicd-migrations-canary-and-rollback.md#核心概念) | 先把少量真实流量切到新版本，用指标对比决定放量还是撤回。 |
| [基础设施即代码（IaC）](../01-traditional-solutions/06-build-test-deliver/10-cloud-kubernetes-and-iac.md#核心概念) | 把基础设施写成可评审、可版本管理的声明式文件，由工具执行并记账。 |
| [漂移](../01-traditional-solutions/06-build-test-deliver/10-cloud-kubernetes-and-iac.md#核心概念) | 实际状态偏离期望状态，多因手工改控制台、脚本漏跑或资源被绕过删除。 |
| [可观测性](../01-traditional-solutions/07-operate-and-optimize/01-logs-metrics-tracing-and-alerting.md#核心概念) | 只依据系统对外输出的事实推断内部状态，不用改代码插断点。 |
| [关联标识（Correlation ID）](../01-traditional-solutions/07-operate-and-optimize/02-correlation-id-and-request-tracing.md#核心概念) | 一个业务事务的稳定标识，从建单到终态不变。 |
| [OpenTelemetry](../01-traditional-solutions/07-operate-and-optimize/03-opentelemetry-prometheus-grafana.md#核心概念) | 遥测信号产生与传输的规范加实现，含 API、SDK 与 Collector。 |
| [SLI](../01-traditional-solutions/07-operate-and-optimize/04-sli-slo-sla-and-error-budget.md#核心概念) | 用可观测数据算出的服务质量数值，通常写成好事件除以有效事件。 |
| [SLO](../01-traditional-solutions/07-operate-and-optimize/04-sli-slo-sla-and-error-budget.md#核心概念) | SLI 在指定窗口内要达到的目标值，是内部工程目标。 |
| [错误预算](../01-traditional-solutions/07-operate-and-optimize/04-sli-slo-sla-and-error-budget.md#核心概念) | 1 减 SLO，是一个窗口内允许出现的坏事件总量。 |
| [燃尽率](../01-traditional-solutions/07-operate-and-optimize/04-sli-slo-sla-and-error-budget.md#核心概念) | 当前错误率除以预算允许的错误率，表示错误预算的消耗速度。 |
| [容量模型](../01-traditional-solutions/07-operate-and-optimize/05-performance-capacity-and-cost.md#核心概念) | 把业务峰值、请求耗时和资源上限换算成可持续承载量并指出瓶颈的判断。 |
| [复盘](../01-traditional-solutions/07-operate-and-optimize/06-incident-response-and-postmortem.md#核心概念) | 事件结束后对时间线、影响、促成因素与改进项的结构化回顾。 |
| [Token](../02-ai-solutions/01-ai-foundations/03-transformer-and-llm-intuition.md#核心概念) | 模型处理文本与计费的最小单位，切分方式由分词器决定。 |
| [上下文窗口](../02-ai-solutions/01-ai-foundations/04-tokens-context-and-attention.md#核心概念) | 一次请求可容纳的输入与输出 token 总量上限，随模型版本变化。 |
| [温度](../02-ai-solutions/01-ai-foundations/05-generation-sampling-and-nondeterminism.md#核心概念) | 生成前缩放 logits 的系数，越小分布越尖、越大越平坦。 |
| [Top-p（核采样）](../02-ai-solutions/01-ai-foundations/05-generation-sampling-and-nondeterminism.md#核心概念) | 只保留累计概率达到 p 的最少候选再抽样，用于截断低质量长尾。 |
| [幻觉](../02-ai-solutions/01-ai-foundations/06-hallucination-and-knowledge-boundaries.md#核心概念) | 模型生成了流畅、但与事实或与本次给定材料不符的内容。 |
| [Embedding](../02-ai-solutions/01-ai-foundations/07-embedding-rerank-and-multimodal-models.md#核心概念) | 把文本映射成定长向量、使语义相近内容向量也相近的过程。 |
| [重排（Rerank）](../02-ai-solutions/01-ai-foundations/07-embedding-rerank-and-multimodal-models.md#核心概念) | 在召回结果上用更强模型二次打分，把真正相关的片段排到前面。 |
| [数据出域](../02-ai-solutions/01-ai-foundations/09-cloud-open-source-local-and-hybrid.md#核心概念) | 数据离开组织控制的网络或合规边界的动作，发往外部服务即成立。 |
| [AI 适配度](../02-ai-solutions/02-discovery-and-requirements/01-identify-ai-suitable-problems.md#核心概念) | 任务交给 AI 后，整体风险仍在组织可接受范围内的程度。 |
| [自动化等级](../02-ai-solutions/02-discovery-and-requirements/01-identify-ai-suitable-problems.md#核心概念) | 同一任务可分为给建议、生成草稿、直接执行三档介入程度。 |
| [混合编排](../02-ai-solutions/02-discovery-and-requirements/02-rules-search-ml-or-llm.md#核心概念) | 按确定性程度把规则、检索与 LLM 串成一条分层处理链路。 |
| [人在回路](../02-ai-solutions/02-discovery-and-requirements/03-user-tasks-and-human-in-the-loop.md#核心概念) | 把关键判断保留给人工确认，系统只提供建议或草稿。 |
| [PoC（概念验证）](../02-ai-solutions/02-discovery-and-requirements/06-poc-pilot-and-production.md#核心概念) | 用最小成本回答技术上能不能做到，参与者多为内部人员。 |
| [试点（pilot）](../02-ai-solutions/02-discovery-and-requirements/06-poc-pilot-and-production.md#核心概念) | 在真实流程中让少量真实用户使用，验证是否值得继续投入。 |
| [指令层级](../02-ai-solutions/03-model-and-prompt/02-instruction-hierarchy-and-system-prompts.md#核心概念) | 不同来源指令冲突时的优先顺序，系统与开发者高于用户和数据。 |
| [System Prompt](../02-ai-solutions/03-model-and-prompt/02-instruction-hierarchy-and-system-prompts.md#核心概念) | 应用开发者写给模型的角色、边界与冲突裁决规则，用户不可见。 |
| [Few-shot](../02-ai-solutions/03-model-and-prompt/03-zero-shot-few-shot-and-examples.md#核心概念) | 在提示词中给出若干条输入输出配对示例，让模型推断格式与尺度。 |
| [提示词模板](../02-ai-solutions/03-model-and-prompt/04-prompt-templates-and-versioning.md#核心概念) | 带占位符的固定文本，运行时注入变量与上下文后再发给模型。 |
| [结构化输出](../02-ai-solutions/03-model-and-prompt/05-structured-output-and-json-schema.md#核心概念) | 用机器可读的结构约束模型生成，而不是解析自由文本。 |
| [流式输出](../02-ai-solutions/03-model-and-prompt/07-streaming-batch-and-async.md#核心概念) | 模型边生成边返回增量，使首字更早出现、改善体感延迟。 |
| [推理模型](../02-ai-solutions/03-model-and-prompt/08-multimodal-and-reasoning-models.md#核心概念) | 先产出大量不可见推理 token 再作答的模型，更贵也更慢。 |
| [向量索引](../02-ai-solutions/04-rag-and-knowledge/02-vector-index-and-vector-databases.md#核心概念) | 为高维向量建立、可快速查找近邻的数据结构。 |
| [ANN（近似最近邻）](../02-ai-solutions/04-rag-and-knowledge/02-vector-index-and-vector-databases.md#核心概念) | 牺牲少量召回换取数量级加速的一类近邻检索策略。 |
| [片段（chunk）](../02-ai-solutions/04-rag-and-knowledge/04-chunking-and-context-preservation.md#核心概念) | 入库、向量化与检索的最小文本单元，边界只能落在原子单元之间。 |
| [混合检索](../02-ai-solutions/04-rag-and-knowledge/05-hybrid-search-and-query-rewriting.md#核心概念) | 同时跑关键词与向量两路召回、再融合排序的做法。 |
| [RRF（倒数排名融合）](../02-ai-solutions/04-rag-and-knowledge/05-hybrid-search-and-query-rewriting.md#核心概念) | 只用各路名次做加权求和的多路融合方法，不依赖原始分数。 |
| [查询改写](../02-ai-solutions/04-rag-and-knowledge/05-hybrid-search-and-query-rewriting.md#核心概念) | 把用户原话改写成更适合检索的查询，同时保留原始实体。 |
| [引用（citation）](../02-ai-solutions/04-rag-and-knowledge/07-citations-and-grounded-answers.md#核心概念) | 回答中指向来源位置的标记，应能回到原文与具体版本。 |
| [权限感知检索](../02-ai-solutions/04-rag-and-knowledge/08-permission-aware-retrieval.md#核心概念) | 检索时按调用者能读什么先过滤，而不是先取回再删。 |
| [Graph RAG](../02-ai-solutions/04-rag-and-knowledge/11-graph-rag-and-rag-vs-alternatives.md#核心概念) | 先抽取实体与关系建图、再在图上检索的 RAG 变体。 |
| [Function Calling](../02-ai-solutions/05-tools-and-agents/01-function-calling-mechanics.md#核心概念) | 模型输出结构化的调用意图，参数校验与真正执行都在应用侧。 |
| [工具描述](../02-ai-solutions/05-tools-and-agents/02-tool-schemas-and-descriptions.md#核心概念) | 模型看到的自然语言说明，决定模型会不会选中这个工具。 |
| [Workflow](../02-ai-solutions/05-tools-and-agents/04-workflow-vs-agent.md#核心概念) | 由代码预先定好路径、把模型与工具按固定顺序串联的编排。 |
| [Agent](../02-ai-solutions/05-tools-and-agents/04-workflow-vs-agent.md#核心概念) | 由模型在循环中自行选择工具与终止条件的执行方式。 |
| [自主性预算](../02-ai-solutions/05-tools-and-agents/04-workflow-vs-agent.md#核心概念) | 对 Agent 的步数、工具范围和花费设定的硬上限。 |
| [审批断点](../02-ai-solutions/05-tools-and-agents/05-state-machines-branches-and-approval.md#核心概念) | 流程暂停、运行态落库并等待人工决定的节点。 |
| [短期记忆](../02-ai-solutions/05-tools-and-agents/07-session-and-memory.md#核心概念) | 单次会话内的消息历史与中间状态，会话结束即失效。 |
| [MCP](../02-ai-solutions/05-tools-and-agents/08-mcp-and-single-vs-multi-agent.md#核心概念) | 用 JSON-RPC 标准化向模型应用暴露上下文与工具的开放协议。 |
| [沙箱](../02-ai-solutions/05-tools-and-agents/09-tool-reliability-sandbox-and-failure-modes.md#核心概念) | 限制工具可触达的文件系统、网络与命令的资源边界。 |
| [请求信封](../02-ai-solutions/06-ai-application-architecture/01-production-ai-request-path.md#核心概念) | 随请求传递的元数据，含 trace、租户、用户与配置版本坐标。 |
| [适配层](../02-ai-solutions/06-ai-application-architecture/03-model-adapter-and-ai-gateway.md#核心概念) | 把各供应商的请求、响应与错误翻译成统一模型的代码层。 |
| [AI 网关](../02-ai-solutions/06-ai-application-architecture/03-model-adapter-and-ai-gateway.md#核心概念) | 模型流量的统一入口，负责密钥、鉴权、配额、日志与缓存。 |
| [语义缓存](../02-ai-solutions/06-ai-application-architecture/06-versioning-and-caching.md#核心概念) | 用向量相似度判断问题是否等价来复用答案，代价是可能误命中。 |
| [版本坐标（bundle）](../02-ai-solutions/06-ai-application-architecture/06-versioning-and-caching.md#核心概念) | 把 Prompt、模型、知识库与检索配置组合成的不可变引用。 |
| [成本归属](../02-ai-solutions/06-ai-application-architecture/07-rate-limiting-quota-and-cost-attribution.md#核心概念) | 把费用按租户、功能、模型与版本分摊，用于分析与定价。 |
| [混淆代理](../02-ai-solutions/06-ai-application-architecture/08-sso-rbac-and-permission-propagation.md#核心概念) | 高权限服务被低权限用户诱导，代其执行原本无权做的操作。 |
| [黄金集（Golden Dataset）](../02-ai-solutions/07-evaluation-security-governance/02-golden-datasets-and-sample-design.md#核心概念) | 人工确认过期望答案与期望行为、用于判定质量的样本集合。 |
| [忠实度](../02-ai-solutions/07-evaluation-security-governance/03-correctness-relevance-faithfulness.md#核心概念) | 回答中每条断言都能由本次检索到的上下文推出。 |
| [误差传播](../02-ai-solutions/07-evaluation-security-governance/04-layered-and-end-to-end-evaluation.md#核心概念) | 上游环节的错误向下游传递并被放大，使端到端结果变差。 |
| [LLM-as-a-Judge](../02-ai-solutions/07-evaluation-security-governance/06-human-review-and-llm-as-a-judge.md#核心概念) | 用模型按量表给答复打分或做两两比较的自动评测方式。 |
| [回归门禁](../02-ai-solutions/07-evaluation-security-governance/07-regression-ab-and-online-evaluation.md#核心概念) | 断言失败即阻断发布的检查，不靠平均分蒙混过关。 |
| [影子流量](../02-ai-solutions/07-evaluation-security-governance/07-regression-ab-and-online-evaluation.md#核心概念) | 把生产请求复制给新版本、只记录不返回给用户的验证手段。 |
| [Prompt Injection](../02-ai-solutions/07-evaluation-security-governance/08-prompt-injection-and-data-exfiltration.md#核心概念) | 把指令伪装成内容注入上下文，让模型执行未授权行为。 |
| [间接注入](../02-ai-solutions/07-evaluation-security-governance/08-prompt-injection-and-data-exfiltration.md#核心概念) | 载荷藏在检索文档、评价或工具返回里的注入，攻击者常是第三方。 |
| [过度代理](../02-ai-solutions/07-evaluation-security-governance/10-excessive-agency-guardrails-and-approval.md#核心概念) | 模型被授予超出任务所需的工具、权限或自主性。 |
| [Guardrail](../02-ai-solutions/07-evaluation-security-governance/10-excessive-agency-guardrails-and-approval.md#核心概念) | 模型之外的输入、输出与工具三层约束，任何一层失效都不应越权。 |
| [托管 API](../02-ai-solutions/08-deploy-operate-optimize/01-hosted-api-self-hosted-and-hybrid.md#核心概念) | 由供应商提供模型与推理算力、按 token 计费的服务形态。 |
| [自建推理](../02-ai-solutions/08-deploy-operate-optimize/01-hosted-api-self-hosted-and-hybrid.md#核心概念) | 在自有 GPU 上部署推理引擎，权重与请求都在自己网络内。 |
| [首 Token 延迟（TTFT）](../02-ai-solutions/08-deploy-operate-optimize/03-concurrency-throughput-and-latency.md#核心概念) | 从请求到达到收到第一个输出 token 的时间，决定是否感觉卡住。 |
| [goodput](../02-ai-solutions/08-deploy-operate-optimize/03-concurrency-throughput-and-latency.md#核心概念) | 满足 SLO 的那部分请求吞吐，衡量真正有用的产能。 |
| [自耗时](../02-ai-solutions/08-deploy-operate-optimize/05-ai-tracing-and-observability.md#核心概念) | span 总耗时减去其子 span 耗时，用来定位时间花在哪一层。 |
| [分层排障](../02-ai-solutions/08-deploy-operate-optimize/06-troubleshooting-prompt-retrieval-model-tools.md#核心概念) | 按数据流顺序逐层验证，先定位层再定位根因的排查方法。 |
| [模型漂移](../02-ai-solutions/08-deploy-operate-optimize/08-provider-limits-model-drift-and-runbook.md#核心概念) | 线上数据分布或模型行为变化，使效果在无新版发布时缓慢下滑。 |
| [Runbook](../02-ai-solutions/08-deploy-operate-optimize/08-provider-limits-model-drift-and-runbook.md#核心概念) | 面向值班人员的可执行处置手册，含分级、判定、动作与升级路径。 |
