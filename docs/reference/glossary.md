# 术语表

| 术语 | 定义 |
| --- | --- |
| 解决方案 | 针对业务目标的一组技术、流程和交付安排。 |
| 解决方案架构 | 描述组件、边界、关系、约束和关键决策的设计。 |
| [利益相关者](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#利益相关者地图) | 受方案影响、能够影响方案或拥有关键信息的人或组织。 |
| [发起人](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#利益相关者地图) | 为项目提供方向、授权或资源的人。 |
| [业务目标](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#目标产出和成果) | 组织希望通过行动取得的结果。 |
| [产出](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#目标产出和成果) | 项目直接交付的产品、功能或文档。 |
| [成果](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#目标产出和成果) | 产出被使用后带来的可观察变化。 |
| [指标](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#目标产出和成果) | 用于判断目标或质量是否达成的可测量值。 |
| [关注点](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#关注点与冲突) | 利益相关者希望方案保护、改善或避免的事项。 |
| [决策所有者](../01-traditional-solutions/01-discovery-and-requirements/02-stakeholders-and-business-goals.md#利益相关者地图) | 对某类决定拥有最终授权的人。 |
| [功能需求](../01-traditional-solutions/01-discovery-and-requirements/05-functional-and-non-functional-requirements.md#核心概念) | 描述系统必须执行的行为。 |
| [质量属性](../01-traditional-solutions/01-discovery-and-requirements/05-functional-and-non-functional-requirements.md#核心概念) | 描述系统在特定条件下应达到的质量。 |
| [质量属性场景](../01-traditional-solutions/01-discovery-and-requirements/05-functional-and-non-functional-requirements.md#核心概念) | 用刺激源、刺激、环境、对象、响应和响应度量描述质量要求的结构。 |
| [可测量需求](../01-traditional-solutions/01-discovery-and-requirements/05-functional-and-non-functional-requirements.md#工作原理) | 明确条件、刺激、响应、阈值和验证方法，使团队能够判断需求是否达成。 |
| 约束 | 限制方案选择或交付方式的条件。 |
| 假设 | 尚未验证、但当前方案暂时依赖的判断。 |
| 交付物 | 生命周期某阶段产生并交给他人使用的结果。 |
| 验收标准 | 用于判断某项需求是否完成的可验证条件。 |
