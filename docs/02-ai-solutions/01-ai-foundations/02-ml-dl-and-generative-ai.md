# 机器学习、深度学习与生成式 AI

## 为什么需要学习

晴空商城的售后助手最初把“退款原因分类”也交给大语言模型：把客户留言丢进去，让模型判断属于“质量问题、物流破损、描述不符、不想要了”中的哪一类。结果是每条分类要花一次完整生成的钱，延迟 2 秒以上，而且同一句话问两遍偶尔给出不同类别，统计报表因此每天对不上。

后来团队换成一个几十行的朴素分类器，准确率相近，延迟降到毫秒级，成本几乎为零。问题不在“模型太弱”，而在**用生成式模型做了判别式任务**。分不清这两类任务，选型就只能靠猜。

> **核心结论：** 判别式解决“这是哪一类”，生成式解决“接下来该出现什么”；把两者用错位置，是最常见的成本与稳定性浪费。

## 学习目标

完成本课后，你能够：

- 解释 *机器学习*、*监督学习*、*判别式模型*、*生成式模型*、*训练*、*推理*、*分布漂移*。
- 用对照表说明两类任务在输入、输出、评价指标上的差别。
- 把大语言模型定位到“规则 → 统计机器学习 → 深度学习 → Transformer”的技术谱系中。
- 针对售后助手的三个子任务，分别选出合适的模型类型并说明理由。

## 业务场景

售后助手实际包含三个不同类型的子任务：

- **分类**：客户这句话属于哪种退款原因？输出是 4 个固定类别之一。
- **抽取**：从订单备注与对话里抽出“订单号、商品、故障描述、期望动作”。输出是结构化字段。
- **生成**：把政策条款、订单状态和客户情绪组织成一段得体、准确、可读的答复。

三者对“错”的容忍度完全不同：分类错了，报表偏差；抽取错了，可能退错钱；生成错了，客户被误导。本课只看一个侧面：**同一套链路里，不同子任务应该用不同技术，而不是统一塞给一个大模型。**

## 核心概念

*机器学习* 指从数据中自动归纳规律，而不是由人把规则一条条写死。传统程序是“人写规则、机器执行”，机器学习是“人给数据和目标、机器找规则”。

*监督学习* 是最常见的形式：给一批“输入 + 正确答案”的样本，让模型学会从输入映射到答案。晴空商城的历史工单（留言 + 已标注的退款原因）就是监督学习数据。

*判别式模型* 学习的是“给定输入，各类别的概率或边界”，例如判断一句话属于哪类退款原因。它只需要回答“是哪类”，不需要会写句子。

*生成式模型* 学习的是“数据的分布”，能够产生新的内容，例如续写一段答复、生成一张图、把一段语音转成文字。

*训练* 是用数据调整模型参数的过程，成本高、周期长、产出是一个模型版本。*推理* 是用训练好的模型处理新请求，成本与延迟按次计算。

*分布漂移* 指线上数据的分布随时间偏离训练数据。例如商城上线“预售”玩法后，留言里大量出现训练时没见过的“预售尾款”，分类准确率就会下降。

| 对照面 | 判别式模型 | 生成式模型 |
| --- | --- | --- |
| 回答的问题 | 这是哪一类、这个值是多少 | 接下来最可能是什么内容 |
| 输出形态 | 标签、分数、结构化字段 | 自然语言、代码、图像、音频 |
| 训练数据要求 | 需要标注好的答案 | 大量原始文本或配对数据 |
| 评价方式 | 准确率、召回率、F1、AUC | 人工评分、事实一致性、任务通过率 |
| 单次成本 | 通常极低 | 显著更高，随输入输出长度增长 |
| 典型错误 | 边界样本判错，长尾覆盖差 | 事实错误、跑题、格式不稳定 |
| 晴空商城示例 | 退款原因分类、欺诈识别、意图识别 | 答复撰写、政策改写、工单摘要 |

### 技术谱系

| 阶段 | 主要特点 | 与售后助手的关系 |
| --- | --- | --- |
| 规则系统 | 人工写 if/else 与关键词 | 处理“退货”“退款”等高频明确词最省钱 |
| 统计机器学习 | 人工设计特征 + 传统算法（如逻辑回归、树模型） | 分类、排序、风控的主力，可解释、便宜 |
| 深度学习 | 多层神经网络自动学特征 | 图像、语音、文本分类效果明显提升 |
| Transformer 与大语言模型 | 注意力机制 + 海量预训练 + 生成式目标 | 承担答复生成、复杂理解、跨格式转换 |
| 多模态模型 | 同时处理文本、图像、音频、文档 | 处理客户上传的破损照片与发票 |

**结论：大语言模型是谱系中的一层，不是替代其余各层的终点。**

## 工作原理

### 训练一个判别式模型

1. 收集历史工单，人工标注退款原因，形成样本集。
2. 把文本转成特征：关键词是否出现、长度、是否含“破损”等词。
3. 选择算法（逻辑回归、树模型或小型神经网络），用训练集拟合参数。
4. 用验证集调参，避免只记住训练样本（过拟合）。
5. 用从未参与的测试集评估准确率与召回率，形成基线。
6. 上线后按周抽样复核，发现分布漂移就补样本重训。

### 训练一个大语言模型（生成式）

1. 收集海量文本，做清洗与去重。
2. *预训练*：让模型反复做“预测下一个 token”的任务，学会语言规律与世界知识。
3. *后训练*：用指令数据与人类偏好数据调整行为，让它更会按要求回答。
4. 部署为推理服务，接收提示词并逐 token 生成输出。
5. 通过提示词、检索、工具或微调适配具体业务。

### 推理阶段发生了什么

1. 输入文本被切成 token 序列。
2. 模型逐层计算，得到“下一个 token 的概率分布”。
3. 按采样策略选一个 token，追加到序列末尾。
4. 重复直到结束标记或长度上限。

判别式模型只做一次判断就结束；生成式模型要重复很多次，因此**生成式推理成本大约按输出长度线性累加**。

## 架构与选型

| 子任务 | 首选 | 备选 | 不推荐 | 依据 |
| --- | --- | --- | --- | --- |
| 退款原因分类 | 小型判别式模型 | 规则 + 关键词兜底 | 每次调用大模型生成 | 类别固定、量大、要求稳定 |
| 订单字段抽取 | 结构化输出的大模型，或小模型微调 | 正则 + 模板 | 自由文本生成后再解析 | 需要字段级校验 |
| 答复撰写 | 生成式大模型 + 检索 + 人工确认 | 模板 + 槽位填充 | 纯规则模板 | 需要语言组织与情绪适配 |
| 破损照片判断 | 多模态模型或专用视觉模型 | 人工审核 | 纯文本模型 | 输入含图像 |
| 高风险动作（退款） | 确定性规则 + 工具 | 模型建议 + 人工确认 | 模型直接执行 | 不可逆、需审计 |

选型依据可以概括成三问：**输出空间是封闭还是开放？错一次的代价多大？请求量与延迟要求如何？**封闭、代价高、量大 → 判别式或规则；开放、可人工复核、量适中 → 生成式。

## 最小示例

下面两个脚本用标准库演示“同一批数据、两种范式”。先准备 `tickets.json`：

```json
[
  {"text": "屏幕有亮点", "label": "quality"},
  {"text": "外包装破了", "label": "logistics"},
  {"text": "和图片不一样", "label": "mismatch"},
  {"text": "不想要了", "label": "changed_mind"},
  {"text": "收到就是坏的", "label": "quality"},
  {"text": "快递摔坏了", "label": "logistics"}
]
```

判别式：用关键词计数做最朴素的分类。

```python
import json

with open("tickets.json", encoding="utf-8") as handle:
    rows = json.load(handle)           # 读取标注样本，模拟训练集

KEYWORDS = {                            # 人工特征：把这几个词当作判别信号
    "quality": ["坏", "亮点", "故障"],
    "logistics": ["破", "摔", "快递"],
    "mismatch": ["不一样", "图片"],
    "changed_mind": ["不想要"],
}

def classify(text):
    scores = {label: 0 for label in KEYWORDS}
    for label, words in KEYWORDS.items():
        scores[label] = sum(word in text for word in words)  # 命中即加分
    best = max(scores, key=scores.get)
    return best if scores[best] > 0 else "unknown"            # 全不命中就拒判

correct = sum(classify(row["text"]) == row["label"] for row in rows)
print(f"accuracy: {correct}/{len(rows)}")
print(classify("快递把盒子摔破了"))
print(classify("这个颜色和图片不一样"))
```

预期输出：

```text
accuracy: 6/6
logistics
mismatch
```

生成式：用二元语法（bigram）从同样的语料里“接着说”。

```python
import json
import random

with open("tickets.json", encoding="utf-8") as handle:
    texts = [row["text"] for row in json.load(handle)]

pairs = {}                              # 记录每个字后面出现过哪些字
for text in texts:
    for current, nxt in zip(text, text[1:]):
        pairs.setdefault(current, []).append(nxt)

random.seed(7)                          # 固定随机种子，保证结果可复现
current, out = random.choice(list(pairs)), ""
for _ in range(6):                      # 只生成 6 个字，够看出“续写”而非“判断”
    out += current
    current = random.choice(pairs.get(current, list(pairs)))
print("generated:", out)
```

预期输出（`seed=7` 与上面的语料顺序下实测得到；换语料顺序结果会变）：

```text
generated: 片不想要了就
```

两个脚本的关键差别是：**第一个脚本输出的是封闭集合里的一个标签，第二个脚本输出的是语料里出现过的字符序列**。前者可以直接进报表，后者需要人来判断是否有意义。真实的大语言模型只是把第二步的统计从“字”换成“子词”，把参数从几百个换成几十亿个，范式并没有变。

## 动手实验

**前置条件**：Python 3.9+；无需网络与密钥。

1. 新建目录，写入 `tickets.json`、`classify.py`、`generate.py`。
2. 运行 `python3 classify.py`，记录准确率。
3. 把 `quality` 的关键词列表清空，再运行，观察准确率下降与 `unknown` 增多。
4. 运行 `python3 generate.py` 两次，第二次把 `random.seed(7)` 改成 `random.seed(8)`，比较输出差异。
5. 预期结果：分类脚本输出 `accuracy: 6/6`（清空关键词后下降）；生成脚本每次输出不同但都是训练语料中出现过的字的组合。
6. **验证方法**：用“预售尾款不想付了”这条新表达测试分类器。实测结果是 `unknown`——它没命中任何关键词，这就是分布漂移的最小演示。
7. **清理方法**：删除实验目录即可，无外部副作用。

## 常见错误与排查

| 现象 | 可能原因 | 验证方法 | 修复方向 |
| --- | --- | --- | --- |
| 分类结果每次不一样 | 用生成式模型做分类且未固定采样 | 同一输入重复 5 次，看标签是否变化 | 换判别式模型，或固定随机性并做多数投票 |
| 分类成本高、延迟大 | 模型选择与任务不匹配 | 看单次请求 token 数与 P95 延迟 | 换成小模型或传统分类器 |
| 上线三个月后准确率下滑 | 分布漂移，训练数据未更新 | 对比新旧样本的关键词分布 | 建立抽样复核与定期重训 |
| 抽取字段总是缺几个 | 用自由生成再解析，格式不稳定 | 统计解析失败率 | 改用结构化输出或字段级校验 |
| 人称“我们训练了一个模型”但只有 Prompt | 混淆了提示词工程与训练 | 检查是否有参数更新与训练数据 | 明确术语，避免误导决策 |
| 生成答复很长但没信息 | 目标是“像人说话”，不是“解决问题” | 人工评分项里是否有“可执行结论” | 明确输出契约与评分维度 |

## 安全与生产注意事项

**<u>把生成式模型放在需要确定性的位置（金额计算、权限判断、退款执行），会造成不可复现的生产事故。</u>**缓解方法：这类逻辑用确定性代码实现，模型只能提供参数建议，且必须经过校验与人工确认。

**<u>训练数据里可能含有客户个人信息，直接用于训练或微调会造成数据泄露。</u>**缓解方法：训练前做去标识化与字段白名单，记录数据来源与授权范围，保留可删除能力。

另外：微调不是知识更新的手段，政策变更应改检索库。

## 本课总结

- **判别式回答“是哪一类”，生成式回答“接下来是什么”，选错范式是最常见的浪费。**
- 训练是离线、昂贵、产出模型版本；推理是在线、按次计费、决定延迟与成本结构。
- 大语言模型是“规则 → 机器学习 → 深度学习 → Transformer”谱系中的一层，不替代其他层。
- 判断该用哪类模型的三问：输出空间封闭吗、错一次代价多大、请求量与延迟要求如何。
- 生成式输出必须配结构化校验与人工确认，尤其在涉及资金与权限的动作上。

参考思路：风险包括格式不稳定导致分类不可统计、成本与延迟高于拆分方案、错误难归因。可做的实验：同一批 100 条工单分别跑“合并调用”与“分类 + 抽取 + 生成”三段式，比较字段完整率、标签一致性、P95 延迟与单条成本。

## 小测

1. 判断：大语言模型属于判别式模型。对还是错？
2. 下列哪个任务最适合判别式模型？  
   A. 写一封道歉邮件　B. 判断工单是否属于“物流破损”　C. 把政策改写得更易懂　D. 生成工单摘要
3. 为什么生成式推理的成本与输出长度相关？
4. 什么是分布漂移？举一个售后场景的例子。
5. 场景题：产品经理要求“把退款原因分类也换成最新的大模型，因为效果最好”。你如何回应？

## 答案与解析

1. **错。**大语言模型的主体是在做“预测下一个 token”的生成式任务，它可以在提示下完成分类，但那只是生成能力的一种用法，本质仍是生成式；专用分类器才是判别式。
2. **B。**输出是封闭类别集合，样本充足、要求稳定。A、C、D 都需要组织语言，属于生成式更合适的范围。
3. 因为生成是逐 token 进行的，每生成一个 token 都要跑一遍前向计算，序列越长计算越多；而判别式只需一次前向就得到结果。
4. 线上数据分布偏离训练数据。例如商城新增“预售”玩法后，留言里大量出现“预售尾款”这类训练时没见过的表达，关键词分类器只能返回 `unknown`。
5. 回应思路：先问指标。分类任务关心准确率、稳定性、延迟与成本，而不是“模型是否最新”。可提出对比实验：同一测试集上比较新旧方案的四项指标，若生成式方案在准确率上没有显著优势而成本与延迟明显更高，就保留判别式方案；若长尾表达确实处理不好，再考虑“判别式为主 + 生成式兜底”的混合结构。
