# 幻觉、知识边界与非确定性

## 为什么需要学习

售后助手在某周的抽检里暴露了三个问题：答复写“支持 30 天无理由退货”，而政策是 7 天；给客户提供了一个不存在的退货物流单号；在客户追问“你们第 4.2 条怎么写的”时，自信地引用了政策里根本不存在的小节编号。

这三个错误都不是“模型没听懂”，而是**模型在用最像答案的方式填补空缺**。它没有“不知道”的默认动作，也没有查证事实的能力。解决方案能做的是：把事实从模型参数里拿走，放到可检索、可校验的地方，并让“无法证实”的输出在系统里被判为失败。

> **核心结论：** 幻觉不是靠更好的提示词消除的缺陷，而是必须用“外部事实源 + 引用 + 校验”的结构去兜住的系统性风险。

## 学习目标

完成本课后，你能够：

- 解释 *幻觉*、*事实性幻觉*、*忠实性幻觉*、*知识截止*、*引用校验*、*拒答*。
- 用三层知识边界判断一个业务问题应由参数、上下文还是工具回答。
- 写出一个带引用字段的输出结构，并用脚本验证“引用确实存在于事实源中”。
- 列出至少四项产品化对策，并说明各自能覆盖哪一类幻觉。

## 业务场景

客户来信：“我 10 月 12 日签收的吹风机，用了两天发现风力变小，能退吗？运费谁出？你们政策第几条写的？”

一个合格的答复需要三个事实：签收时间与时效（来自订单 + 政策）、运费承担规则（来自政策）、条款编号（来自政策原文）。这三者都不在模型参数里，必须在本次请求中被检索出来并逐条引用。

本课只看这个侧面：**当事实不在模型脑子里时，答案必须来自哪里，以及如何证明它真的来自那里。**

## 核心概念

*幻觉* 指模型生成了流畅但与事实不符、或与给定材料不符的内容。

按成因可以分为两类：*事实性幻觉* 是内容与世界事实不符（例如把 7 天说成 30 天）；*忠实性幻觉* 是内容与本次提供的材料不符（材料里写了 15 天，模型却总结成 7 天）。前者要靠外部事实源，后者要靠引用与一致性校验。

*知识截止* 指模型参数知识的最后更新时间。截止之后发生的事情，模型只能猜；而它往往猜得很像真的。

*引用校验* 是程序化检查：答复里每条结论都带一个来源标识与原文片段，程序核对“这个标识存在、这个片段确实是来源里的原文”。它是目前性价比最高的事实防幻觉手段。

*拒答* 是模型或系统在证据不足时明确说“无法确认，需要人工核实”。拒答率是必须被测量的指标：拒答太少会瞎编，拒答太多则产品不可用。

| 幻觉类型 | 典型表现 | 主要成因 | 有效对策 |
| --- | --- | --- | --- |
| 事实性幻觉 | 政策时效、金额、条款号说错 | 参数知识不可靠、有截止日期 | 检索 + 引用 + 程序校验 |
| 忠实性幻觉 | 摘要与原文相反、漏掉例外 | 长上下文稀释、生成路径依赖 | 分段处理、要求逐条引用、一致性检查 |
| 编造实体 | 不存在的物流单号、订单号 | 模型没有“未知”这一动作 | 结构化字段只能来自工具返回值 |
| 过度推断 | 把“可申请”说成“必定通过” | 训练偏好确定语气 | 提示词约束 + 合规词过滤 |
| 工具参数幻觉 | 调用退款工具时金额填错 | 参数由模型自由生成 | 参数必须来自工具/数据库查询结果 |
| 引用幻觉 | 引用不存在的小节编号 | 引用也是生成的文本 | 引用 id 白名单 + 原文比对 |

## 工作原理

1. **问题分类**：判断问题需要事实（政策、订单、时效），还是只需要表达（改写、解释）。
2. **获取事实**：事实类问题走检索或工具，拿到带 id 的原文片段或结构化返回值。
3. **限定证据范围**：只有被检索到的片段可以进入上下文，且明确标注为“唯一事实来源”。
4. **要求引用**：输出结构中强制包含 `claims[].citations[]`，每条结论都要指向片段 id 与原文摘录。
5. **程序校验**：核对 id 是否存在、摘录是否为原文子串、金额与时效是否与结构化字段一致。
6. **降级与拒答**：校验失败时不对外发布，改为“需人工核实”，并记录失败样本。
7. **回收与迭代**：把失败样本按类型归类，补检索、补口径、补测试用例。

### 三层知识边界

| 层次 | 内容来源 | 时效性 | 可否引用 | 适用问题 |
| --- | --- | --- | --- | --- |
| 参数知识 | 预训练语料 | 有截止日期 | 不可 | 语言组织、通用常识、写作风格 |
| 上下文知识 | 本次请求中提供的片段 | 取决于数据源 | 可（带片段 id） | 政策问答、文档摘要 |
| 工具知识 | 实时接口返回值 | 实时 | 可（带请求 id） | 订单状态、退款结果、库存 |

**结论：事实必须落在上下文知识或工具知识里，参数知识只负责“怎么说”。**

关于成因，OpenAI 在 2025 年发布的幻觉分析文章中指出：模型倾向于给出猜测而不是承认不确定，这与训练和评测的激励方式有关（该结论来自论文摘要层面的阅读，具体论证以原文为准）。这解释了一个反直觉的现象——**模型在不知道时更可能编得像，而不是更容易说“不知道”**。

## 架构与选型

| 结构 | 覆盖的幻觉类型 | 不适用场景 | 代价 |
| --- | --- | --- | --- |
| 纯提示词约束（“不确定就说不知道”） | 少量过度推断 | 事实密集、政策多变 | 最低，但不可验证 |
| 检索 + 强制引用 | 事实性幻觉、引用幻觉 | 知识无法文档化 | 需维护知识库与召回评测 |
| 检索 + 引用 + 程序校验 | 事实性与引用幻觉 | 需要逐字一致的严格场景 | 实现成本中等，收益最高 |
| 工具直取结构化字段 | 编造实体、参数幻觉 | 无对应接口 | 需接口开发与权限设计 |
| 人工复核闸门 | 所有类型的残余风险 | 高频、低风险咨询 | 人力成本，延迟上升 |

选型依据：**先看错误会造成的后果，再看事实源是否可得。**后果不可逆（退款、承诺时效）就必须有工具直取 + 程序校验 + 人工确认；只影响阅读体验的场景，可以用引用 + 抽检。

## 最小示例

下面的脚本校验一份带引用的答复：每条结论必须有引用，引用 id 必须存在，摘录必须是原文子串。

```python
import json

SNIPPETS = {                                   # 模拟检索结果库，id 由检索层生成
    "policy#returns": "签收后 7 天内，商品完好可申请无理由退货。",
    "policy#refund": "质量问题退货，运费由卖家承担。",
    "order#20261019001": "订单 20261019001，实付 899 元，状态已签收。",
}

def norm(text):
    return "".join(text.split())               # 去掉空白，避免换行造成误判

answer = {
    "claims": [
        {"text": "可以在签收后 7 天内无理由退货",
         "citations": [{"id": "policy#returns", "quote": "签收后 7 天内，商品完好可申请无理由退货"}]},
        {"text": "退货运费由卖家承担",
         "citations": [{"id": "policy#refund", "quote": "质量问题退货，运费由卖家承担"}]},
        {"text": "该订单实付 899 元",
         "citations": [{"id": "order#20261019001", "quote": "订单 20261019001，实付 998 元"}]},
    ]
}

problems = []
for claim in answer["claims"]:
    if not claim["citations"]:                  # 无引用的结论一律视为未证实
        problems.append((claim["text"], "no citation"))
        continue
    for cite in claim["citations"]:
        source = SNIPPETS.get(cite["id"])
        if source is None:                      # 引用了不存在的来源 id
            problems.append((claim["text"], f"unknown id {cite['id']}"))
        elif norm(cite["quote"]) not in norm(source):
            problems.append((claim["text"], f"quote not found in {cite['id']}"))

print("claims:", len(answer["claims"]), "problems:", len(problems))
for text, reason in problems:
    print("-", text, "|", reason)
```

预期输出（实测）：

```text
claims: 3 problems: 1
- 该订单实付 899 元 | quote not found in order#20261019001
```

注意第三条：结论写 899，摘录里写的是 998，脚本抓到的正是“模型改写引用时把数字换了”的真实故障模式。这类错误人眼抽检很容易漏掉，程序校验几乎零成本。**关键设计是把引用做成一等字段，而不是让模型在句子末尾随手加一个链接。**

## 动手实验

**前置条件**：Python 3.9+，无网络。

1. 保存脚本为 `verify.py` 并运行，确认输出 `problems: 1`。
2. 把第三条的摘录改回 `实付 899 元`，重跑，预期 `problems: 0`。
3. 把第一条的 `id` 改成 `policy#returns-v0`（不存在的 id），重跑，观察 `unknown id` 报错。
4. 删掉某条结论的 `citations` 数组，重跑，观察 `no citation`。
5. **验证方法**：故意在摘录中加一个换行，确认脚本用 `norm` 归一化后仍能匹配，说明校验逻辑对格式噪声不敏感。
6. **清理方法**：删除 `verify.py`。

## 常见错误与排查

| 现象 | 可能原因 | 验证方法 | 修复方向 |
| --- | --- | --- | --- |
| 答复中的时效/金额与政策不一致 | 事实来自参数知识而非检索 | 检查答复是否带引用，引用是否命中原文 | 强制引用 + 程序校验 + 不通过则拒答 |
| 引用链接点开是 404 或空页 | 引用 id 由模型生成而非检索层返回 | 统计引用 id 落在白名单内的比例 | 引用只能从检索结果中选择，禁止自由生成 |
| 模型对不知道的问题也答得很肯定 | 缺少“未知”动作与拒答样例 | 构造 20 个无答案问题测拒答率 | 补拒答样例、加证据门槛 |
| 长文档摘要漏掉关键例外 | 忠实性幻觉，长上下文稀释 | 与人工摘要逐条对比例外项 | 分段摘要 + 逐条引用 + 专门检查例外 |
| 工具调用金额错误 | 参数由模型自由生成 | 核对工具入参与订单数据 | 参数从查询结果直取，模型只做选择 |
| 抽检通过但客户仍投诉 | 抽检样本少且偏易 | 统计投诉样本与抽检样本的重叠度 | 用投诉样本反哺测试集 |

## 安全与生产注意事项

**<u>让模型自己评估“我有多确定”，不能作为发布闸门。</u>**模型给出的置信度或自检结论同样是生成文本，会与错误答案保持一致。缓解方法：用外部信号做闸门——引用是否命中、字段是否通过 schema、金额是否与订单一致、是否命中合规词表。

**<u>没有引用校验就把政策类答复直接发给客户，会把企业口径风险转成法律与赔付风险。</u>**缓解方法：对外答复必须经过引用校验；校验失败的走人工，不允许“先发出去再说”。

补充两点：不要为了让答复“更好看”而允许模型补全缺失字段，缺失就应显示“待核实”；日志需记录每次答复引用了哪些片段与版本号，以便事后追溯是数据问题还是生成问题。

## 本课总结

- **幻觉是结构性风险，靠“外部事实源 + 引用 + 程序校验”兜住，而不是靠提示词祈求。**
- 事实性幻觉与忠实性幻觉成因不同，前者要外部事实源，后者要引用与一致性检查。
- 三层知识边界：参数知识负责表达，上下文与工具知识负责事实。
- 引用必须由检索层返回、模型只能选择，且要能程序化核对到原文。
- 拒答率与引用命中率是必须监控的两个指标，前者防瞎编，后者防假引用。

## 思考题

客服主管提出：“既然模型会编，那就在提示词里写死‘不确定时必须说不知道’，再让模型自己检查一遍答案是否正确。”请评估这个方案能覆盖哪些幻觉、漏掉哪些，并给出你会补充的两项机制。

参考思路：提示词能减少一部分过度推断，模型自检也可能发现明显矛盾，但两者都不可验证——模型可以自信地确认自己的错误答案。漏掉的是引用幻觉、金额与条款号错误、以及参数知识冒充事实。应补充：引用必须来自检索白名单并做原文比对；结构化字段（金额、时效、订单号）必须与订单/政策库的字段做等值校验，不一致直接拦截。

## 小测

1. 材料里写“15 天”，模型总结成“7 天”，这属于哪类幻觉？
2. 为什么“让模型给答案打置信度分数”不是可靠的发布闸门？
3. 判断：只要检索到了正确片段，模型就不会答错。对还是错？
4. 下列哪项最能防止编造物流单号？  
   A. 提高温度　B. 要求模型谨慎　C. 单号只能来自物流接口返回值　D. 增加上下文长度
5. 场景题：抽检发现 5% 的答复引用了不存在的条款编号，但内容本身正确。请给出定位步骤与两条修复措施。

## 答案与解析

1. **忠实性幻觉。**材料在上下文中，模型输出与材料不符，属于不忠实于给定输入；若材料本身没提，模型凭参数知识给出错误时效，则属于事实性幻觉。
2. 因为置信度也是模型生成的文本，与答案同源：答案错时，置信度往往也错，且形式上看起来同样合理。可靠闸门要来自外部可验证信号，例如引用比对、schema 校验、与数据库字段等值比较。
3. **错。**检索到正确片段只是必要条件。片段可能被截断、被长上下文稀释、被模型改写，或与其他片段拼接出错误组合，仍需引用校验与一致性检查。
4. **C。**单号属于客观实体，只能来自权威接口返回值。提高温度会增加随机性，提示谨慎不可验证，加长上下文与实体真实性无关。
5. 定位步骤：先看这些编号是模型自由生成还是检索层返回（比对引用 id 白名单）；再确认检索层是否返回了带编号的片段（可能是分块丢掉了标题层级）；最后看提示词是否鼓励“补充条款号”。修复措施：引用只允许从检索结果中选择并做原文比对；分块时保留标题与小节号作为元数据，答复中的编号必须来自元数据而非生成。
