# 生成、采样、温度与不确定性

## 为什么需要学习

售后助手做验收时，质检团队抽了同一条工单连续生成 10 次：4 次建议“同意退款”，5 次建议“转人工核实”，1 次跑偏去解释运费规则。产品经理的第一反应是“模型不稳定，换一个”。换成另一家模型后现象依旧，只是比例变了。

真正的原因是：**生成本身就是一个按概率抽样的过程**。同一输入在不同随机状态下走出不同路径，这是机制的一部分，不是模型缺陷。解决方案要做的不是消灭它，而是把它约束在可接受范围内，并且让不可接受的波动被检测到。

> **核心结论：** 采样参数决定“多样性”，不决定“正确性”；需要稳定结论的地方，靠结构与校验，不靠调低温度。

## 学习目标

完成本课后，你能够：

- 解释 *logits*、*概率分布*、*温度*、*top-p*、*top-k*、*贪心解码*、*随机种子*、*流式生成*。
- 说明一次生成从概率分布到输出 token 的完整循环，以及每个参数介入的位置。
- 列出至少四个“同一输入结果不同”的原因，并说明哪些可以消除、哪些只能检测。
- 为“退款建议、答复措辞、营销文案”三类输出分别选择采样策略与验证方式。

## 业务场景

晴空商城的售后助手要为每条工单输出两部分：**建议动作**（同意退款 / 换货 / 转人工 / 拒绝）与**客户答复文本**。它们对稳定性的要求完全不同：

- 建议动作会进入统计报表和审批流，同一工单两天跑出两个结论会让财务对不上账。
- 答复文本需要自然、贴合客户情绪，完全一样的模板反而显得敷衍。

本课只看这个侧面：**同一个请求里，不同字段应该有不同的“确定性等级”。**

## 核心概念

*logits* 是模型最后一层输出的原始分数，可正可负、没有上界，本身不是概率。

*概率分布* 是把 logits 经 softmax 归一化后得到的“每个候选 token 的可能性”。*贪心解码* 每次直接取概率最大的 token，不再抽样。

*温度* 是一个缩放系数：模型在做 softmax 前先把 logits 除以温度。温度小于 1 会让分布更尖锐（更倾向最高分候选），大于 1 会让分布更平坦（小概率候选也有机会）。

*top-k* 只保留概率最高的 k 个候选。*top-p*（也叫核采样）保留累计概率达到 p 的最少候选集合。两者都是“截断长尾”，避免低质量 token 被选中。

*随机种子* 是伪随机数生成器的初始状态。固定种子能让同一程序产生同样的随机序列，但**不保证模型输出完全一致**，因为分词、批处理、并行计算与模型版本都会引入差异。

*流式生成* 是首个 token 生成后就开始返回，用户不必等待全文。它改善体感延迟，但带来“中途断开时已有半截内容”的新问题。

| 参数 | 作用位置 | 调高的效果 | 主要风险 |
| --- | --- | --- | --- |
| 温度 | softmax 的输入缩放 | 分布更平、更多样 | 结论漂移、跑题 |
| top-p | 截断候选集合 | 保留更多长尾候选 | 低质量 token 进入 |
| top-k | 截断候选集合 | 候选更多 | 与 top-p 叠加时行为难预测 |
| 最大输出长度 | 停止条件 | 允许更长输出 | 成本上升、被截断风险变化 |
| 随机种子 | 抽样过程 | —— | 只能减少波动，不能保证复现 |
| 停止词 | 终止条件 | —— | 配置错误会截断正常输出 |

## 工作原理

一次生成按以下顺序循环：

1. 模型完成一次前向计算，输出词表上每个 token 的 *logits*。
2. 按温度缩放后做 softmax，得到概率分布。
3. 按 top-k / top-p 截断候选集合，并把剩余候选的概率重新归一化到和为 1。
4. 从截断后的分布中抽样（或取 argmax）得到一个 token。
5. 把该 token 追加到序列末尾，作为下一轮的输入。
6. 重复第 1–5 步，直到生成结束标记、达到最大长度或命中停止词。
7. 开启流式时，每生成一个 token 或一小段就推送给客户端。

### 输入相同、输出不同的四个原因

| 原因 | 是否可消除 | 应对方式 |
| --- | --- | --- |
| 采样随机性 | 可降低（温度、贪心、种子） | 结构化字段用低温度或固定解码 |
| 服务端批处理与硬件浮点差异 | 不可完全消除 | 接受微小波动，用校验而非比对全文 |
| 上下文细微差异（时间戳、会话 id、历史轮次） | 可消除 | 组装上下文时去掉无关变量，固定顺序 |
| 模型或 Prompt 版本变更 | 可消除 | 版本锁定 + 变更记录 + 回归测评 |

<u>“temperature=0 就等于确定”是最常见的误解。</u>它只表示“取概率最高的 token”，而当两个候选概率接近时，服务端的浮点差异或上下文差异仍可能让它们互换。

## 架构与选型

| 输出类型 | 采样策略 | 附加约束 | 验证方式 |
| --- | --- | --- | --- |
| 结构化建议（动作、金额、类别） | 低温度或固定解码 + 结构化输出 | schema 校验、枚举白名单 | 同一输入重复 20 次，统计一致率 |
| 客户答复文本 | 中等温度（0.2–0.5） | 必须带引用、禁用绝对承诺 | 人工抽检 + 事实一致性检查 |
| 多候选供人挑选 | 较高温度 + 多次采样 | 数量与成本上限 | 命中率、人工采纳率 |
| 营销与创意文案 | 高温 + top-p 截断 | 合规词过滤 | 审核流程，而非自动通过 |

选型依据：**先问“这条输出会不会进入自动决策”，再问“错了要多久才能发现”。**进入自动决策的字段，一律降低随机性并加 schema 校验；只给人看的文本，可以适度放宽，但必须保留引用与免责边界。

另外，参数的具体名称、取值范围、默认值在不同厂商之间有差异，部分模型（尤其是推理型模型）对温度等参数的支持与默认行为也不同，**必须以所用厂商的 API 参考为准**，不要照抄别家的配置。

## 最小示例

下面的脚本用标准库演示温度、top-p 与抽样，输入是四个候选动作的 logits。

```python
import math
import random

LOGITS = {"同意退款": 3.2, "转人工核实": 2.4, "拒绝并说明": 1.1, "忽略问题": -2.0}

def softmax(logits, temperature=1.0):
    if temperature <= 0:
        raise ValueError("temperature 必须大于 0；T=0 请改用 argmax")
    m = max(logits.values())                              # 减最大值，防止 exp 溢出
    exps = {k: math.exp((v - m) / temperature) for k, v in logits.items()}
    total = sum(exps.values())
    return {k: v / total for k, v in exps.items()}        # 归一化成概率分布

def top_p(dist, p=0.9):
    ordered = sorted(dist.items(), key=lambda kv: kv[1], reverse=True)
    kept, acc = [], 0.0
    for token, prob in ordered:                           # 按概率从高到低累积
        kept.append((token, prob))
        acc += prob
        if acc >= p:                                      # 累计概率够了就截断
            break
    total = sum(prob for _, prob in kept)
    return {token: prob / total for token, prob in kept}  # 截断后必须重新归一化

def sample(dist, seed):
    rng = random.Random(seed)                             # 固定种子只为教学可复现
    r = rng.random()
    acc = 0.0
    for token, prob in dist.items():
        acc += prob
        if r <= acc:
            return token
    return token

for t in (0.2, 1.0, 1.5):
    dist = softmax(LOGITS, t)
    print(f"T={t}: " + ", ".join(f"{k}={v:.3f}" for k, v in dist.items()))

dist = top_p(softmax(LOGITS, 1.0), 0.9)
print("top_p kept:", list(dist))
print("samples:", [sample(dist, seed) for seed in (1, 2, 3, 4, 5)])
```

预期输出（实测）：

```text
T=0.2: 同意退款=0.982, 转人工核实=0.018, 拒绝并说明=0.000, 忽略问题=0.000
T=1.0: 同意退款=0.634, 转人工核实=0.285, 拒绝并说明=0.078, 忽略问题=0.003
T=1.5: 同意退款=0.536, 转人工核实=0.315, 拒绝并说明=0.132, 忽略问题=0.017
top_p kept: ['同意退款', '转人工核实']
samples: ['同意退款', '转人工核实', '同意退款', '同意退款', '同意退款']
```

读法：温度从 0.2 升到 1.5，最高分候选的概率由 0.982 降到 0.536，也就是说“换一个建议”的概率从 1.8% 升到 46%。top-p=0.9 直接砍掉了 `拒绝并说明` 与 `忽略问题`——这正是客服场景想要的：**在截断层面禁止低质量候选，比指望模型稳定更可靠。**同时注意 5 个种子中有 1 次抽到了“转人工核实”，这就是为什么结构化字段不能只跑一次。

## 动手实验

**前置条件**：Python 3.9+，无网络。

1. 保存代码并运行，记录三组温度下的概率。
2. 把 `LOGITS` 改成 `{"同意退款": 2.4, "转人工核实": 2.3, ...}`（两个候选几乎持平），观察温度 0.2 与 1.0 下的分布差异——这就是“接近打平时最容易漂移”的场景。
3. 把 `top_p` 改成 `0.6` 与 `0.99`，观察保留集合的变化。
4. 把种子列表从 5 个扩到 50 个，统计各动作出现次数，算出经验频率与理论概率的偏差。
5. **验证方法**：断言 `abs(sum(dist.values()) - 1) < 1e-9`，确认截断后重新归一化没被漏掉。
6. **清理方法**：删除 `sample.py`。

## 常见错误与排查

| 现象 | 可能原因 | 验证方法 | 修复方向 |
| --- | --- | --- | --- |
| 同一工单两次给出不同退款建议 | 建议字段用了默认采样参数 | 同输入重复 20 次统计一致率 | 结构化字段改用低温度 + schema 校验 |
| 设了 `temperature=0` 仍有差异 | 上下文含时间戳/会话 id，或服务端浮点差异 | 固定上下文后重跑并对比 | 固定上下文、锁定版本，用校验替代全文比对 |
| 答复变得重复机械 | 温度过低 + 提示词缺少变体要求 | 对比 0.2 与 0.6 的人工评分 | 在可接受区间内适度提高温度 |
| 温度调高后出现违规承诺 | 长尾低质量候选被采样 | 抽样检查含“保证”“一定”的答复 | 用 top-p 截断长尾 + 合规词过滤 |
| 流式中途断开，用户看到半句话 | 网络中断未处理，前端直接展示 | 模拟断网观察前端行为 | 前端标记“未完成”，后端支持重试与幂等 |
| 输出在句中被截断 | 达到最大输出长度 | 记录 `finish_reason` 类字段 | 提高上限或要求分点精简输出 |

## 安全与生产注意事项

**<u>用“更人性化”为理由提高温度，会让涉及资金的建议在高风险工单上随机漂移。</u>**缓解方法：把动作类字段与文本类字段拆成两次调用或两个字段，动作字段使用受控解码并做枚举校验，文本字段才允许一定多样性。

**<u>流式输出中途失败时，半截答复被用户当成完整结论，可能造成错误操作。</u>**缓解方法：前端显示“生成中/已中断”状态，后端把未完成标记为失败并可重试；涉及金额与时效应在最后一次校验通过后才展示操作按钮。

另外两点：不要向用户显示未经校验的原始模型输出作为“政策结论”；采样参数与模型版本要写进配置并纳入变更记录，否则回归测评无法定位差异来源。

## 本课总结

- **采样参数改变的是多样性，不是正确性；稳定性来自结构约束与校验。**
- 温度缩放 logits 的锐度，top-p/top-k 截断候选集合，截断后必须重新归一化。
- 同一输入结果不同有四个来源：采样随机、服务端浮点与批处理、上下文细微差异、版本变更；只有后两者可彻底消除。
- `temperature=0` 只是取最大概率，不保证完全复现；关键字段要靠 schema 校验与重复采样统计。
- 流式生成改善体感延迟，但必须显式处理“未完成”状态。

## 思考题

如果业务方要求“退款建议必须 100% 稳定，答复文本必须每次都不同”，你会如何设计这条链路？请说明拆分的依据、需要监控的指标，以及拆分会带来哪些新成本。

参考思路：把一次生成拆为“受控决策 + 文本表达”两步：决策步骤使用固定解码、枚举约束与规则兜底，并对同一输入做一致性抽检；文本步骤保留中等温度，但从决策结果出发生成，避免自由发挥。指标包括决策一致率、schema 校验通过率、引用正确率、文本人工评分。新成本是两次调用的延迟与费用、以及两步之间的一致性校验逻辑。

## 小测

1. 温度小于 1 时，概率分布会怎样变化？
2. top-p 截断后为什么必须重新归一化？
3. 判断：固定随机种子可以保证模型输出完全一致。对还是错？
4. 下列哪项最适合用高温度采样？  
   A. 退款金额计算　B. 建议动作分类　C. 营销文案候选　D. 政策条款引用
5. 场景题：质检发现同一工单的“建议动作”有 12% 的概率不同。你会先查什么，按什么顺序修复？

## 答案与解析

1. 分布更尖锐：高概率候选被进一步放大，低概率候选被压到接近 0，输出更集中。
2. 因为截断会丢弃一部分概率质量，剩余候选的概率和小于 1；不重新归一化就不是合法分布，抽样阈值也会失真。
3. **错。**种子只固定伪随机序列。上下文差异、服务端批处理与浮点误差、模型版本变更都会造成差异，种子无法消除。
4. **C。**创意场景需要多样候选，供人筛选。A、B 需要确定性，D 需要引用原文与校验，都不适合高温度。
5. 先查“波动是否来自采样”：确认该字段的采样参数与是否使用固定解码；再查上下文是否含时间戳等易变内容；再查两个候选的概率是否接近（接近时必然易翻转）。修复顺序：先固定解码与上下文，再把动作字段改为枚举约束 + 规则兜底，最后用 20 次重复采样统计一致率，把一致率纳入验收指标。
