# 引用、溯源与可信回答

## 为什么需要学习

晴空商城的售后智能助手一期上线两周后，客服发现它经常给出“7 天无理由退货”的答复，而冷冻生鲜其实不支持。更麻烦的是：答复里带着一个链接，点开是讲“通用退货规则”的旧公告，客服以为这就是依据，直接转述给了客户。客诉复盘时，团队答不上来三个问题：这句话来自哪一段？那一段现在还生效吗？如果模型什么都不知道，它为什么不直接说不确定？

> **核心结论：** 可信回答不是“看起来有出处”，而是每一条结论都能被独立复现到具体原文，并且在找不到依据时敢于不回答。

## 学习目标

完成本课后，你能够：

- 区分文档级、段落级、句子级和字段级四种引用粒度及其代价。
- 为一个 RAG 回答接口写出包含来源编号、原文引文和版本日期的引用契约。
- 用 Python 标准库实现引用校验，并给出 accept / abstain / reject 三档决策。
- 判断一次“有引用”的回答是否真的被来源支持。

## 前置知识

- 回看上一课：[Rerank、结果筛选与上下文组装](06-rerank-and-context-assembly.md)。
- 了解 RAG 的基本链路：检索 → 组装上下文 → 生成。
- 知道上下文片段通常带编号进入 Prompt。
- 能读写 JSON，能读懂简单正则表达式。

## 业务场景

客服小林收到工单：“用户买的冷冻虾签收两天，能退吗？”助手的理想行为是：检索到《生鲜类目售后规则》与订单详情，回答“生鲜不支持无理由退货，但可申请质量问题退款”，并在每句后标出规则条款与订单字段。如果只检索到通用退货规则，它应该说明“未找到生鲜类目规则”并转人工，而不是套用 7 天无理由。

这里有三类参与者，各自约束不同：

- 客服：要在 30 秒内判断能否照读，引用必须可点击、可核对。
- 质检与合规：要能按工单回放“当时依据的是哪一版政策”。
- 系统：检索结果可能为空、可能过期、可能互相冲突。

## 核心概念

*引用*（citation）是回答中指向来源位置的标记；*溯源*（provenance）是这条标记背后可被机器复核的链路：文档 ID、版本、切片位置与原文片段。二者常被混为一谈——页面上挂个链接只是引用，能回到“第 3 版第 2 节第 1 段”才是溯源。

*依据粒度*决定复核成本：粒度越细越好核对，也越难让模型稳定输出。*无依据拒答*（abstention）指检索结果不足以支撑结论时，系统明确表达“不知道”或只提供原文，而不是让模型自由发挥。*忠实度*（faithfulness）衡量回答中的断言是否都能由给定上下文推出。

| 粒度 | 标记示例 | 复核成本 | 主要风险 | 适用 |
| --- | --- | --- | --- | --- |
| 文档级 | 《生鲜售后规则》 | 低 | 用户找不到那句话 | 政策首页、公告 |
| 条款/段落级 | 规则 §3.2 | 中 | 切分边界把条件句切走 | 制度、条款、FAQ |
| 句子级 | 原文一句 + 偏移量 | 高 | 模型改写后引文不逐字一致 | 金额、时效、法务表述 |
| 字段级 | 订单 `refund_deadline` | 中 | 字段口径与业务解释不一致 | 订单、库存等结构化数据 |

**引用粒度应由“答错的代价”决定，而不是由模型能力决定。** 涉及金额、时效、责任归属的断言，至少要落到条款级并附原文；闲聊式摘要可以只到文档级。

## 工作原理

一个可审计的引用链路包含以下步骤：

1. **分配稳定 ID**：检索阶段给每个切片编号 `doc_id#version#chunk`，而不是数组下标，避免重排后编号漂移。
2. **带元数据组装**：把标题、生效日期、版本随切片一起送入上下文，并声明“只能引用这些编号”。
3. **先引原文再下结论**：要求模型为每条断言交出支撑它的原文子串，而不是只给编号。
4. **结构化输出**：回答拆成 `claim[]`，每项含 `text`、`source_id`、`quote`。
5. **服务端校验**：来源 ID 必须存在于本次检索结果，`quote` 必须是原文的连续子串；不通过则修复或降级。
6. **覆盖度检查**：统计没有引用的断言比例，超过阈值（例如 20%）视为不可信。
7. **冲突与时序检查**：两条来源结论冲突，或来源生效日期早于当前政策版本时，标记为“需人工确认”。
8. **决策与留痕**：输出 accept / abstain / reject，并把检索 ID、模型版本、校验结果写入审计日志。

第 5 步是整条链路的地基：<u>模型生成的引文编号和引文内容都属于模型输出，天然不可信，必须由服务端重新比对。</u> 这也是厂商原生引用能力的价值所在——例如 Anthropic 的 Citations 功能直接返回指向原文句子的引用结构，官方称其在内部评测中把引用召回准确率提升了最多 15%（该功能 2025-06-23 发布并在 Anthropic API 与 Vertex AI 上正式可用，截至 2026-10-19 的公开说明见延伸阅读）。

## 架构与选型

| 方案 | 做法 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| Prompt 自造引用 | 让模型输出 `[1][2]` | 零成本、易实现 | 编号错位、引文编造 | 内部草稿、低风险问答 |
| 模型原生引用 | 使用厂商的 citations / annotations 结构 | 粒度细、结构化 | 绑定厂商与模型，跨供应商不一致 | 文档问答主链路 |
| 后置对齐 | 生成后用检索结果反查句子 | 与模型解耦 | 只能证明“相似”，不能证明“支持” | 存量系统加固 |
| 抽取式回答 | 只允许拼接原文句子 | 可溯源最强 | 语言生硬、覆盖窄 | 法务、费率、赔付条款 |

选型依据有两条：先看答错的代价，再看是否允许更换模型。如果回答会被客服直接转述给客户，建议“结构化引用 + 服务端校验 + 必要时拒答”，不要依赖模型自觉。

## 最小示例

下面的校验器用标准库模拟第 5、6 步。它要求回答里每条断言写成 `结论【来源编号｜原文引文】`，于是校验退化成精确子串匹配——这正是“抽取式引用”能落地的前提。

```python
import re

# 来源库：键是检索结果的稳定编号，值是原文片段
SOURCES = {
    "S1": "自签收之日起 7 日内，商品未拆封可申请无理由退货。",
    "S2": "生鲜类商品一经签收不支持无理由退货。",
    "S3": "退货审核通过后 3 个工作日内原路退款。",
}

# 模型输出：每条断言后用【来源编号｜原文引文】标注依据
ANSWER = ("生鲜商品不支持无理由退货【S2｜生鲜类商品一经签收不支持无理由退货】。"
          "签收后 7 日内未拆封可以申请退货【S1｜商品未拆封可申请无理由退货】。"
          "退款将在 1 个工作日内到账【S1｜退款将在 1 个工作日内到账】。"
          "如有疑问请联系客服。")

SPLIT = re.compile(r"[。；]")                  # 以句号/分号切分断言
BRACKET = re.compile(r"【(S\d+)｜([^】]+)】")   # 抓取编号与引文

def claims(text):
    return [part.strip() for part in SPLIT.split(text) if part.strip()]

total = uncited = bad_quote = unknown = 0
for claim in claims(ANSWER):
    total += 1
    hits = BRACKET.findall(claim)
    if not hits:                               # 没有引用：记录下来，但不立刻失败
        uncited += 1
        print(f"[无引用] {claim}")
        continue
    for sid, quote in hits:
        if sid not in SOURCES:                 # 引用了不存在的来源
            unknown += 1
            print(f"[未知来源] {sid} <- {claim}")
        elif quote not in SOURCES[sid]:        # 引文必须在原文中逐字出现
            bad_quote += 1
            print(f"[引文不符] {sid} 引文不在原文中：{quote}")
        else:
            print(f"[通过] {sid} {claim[:14]}…")

ratio = uncited / total
if unknown or bad_quote:
    decision = "reject"                        # 有硬错误：拒答并转人工
elif ratio > 0.2:
    decision = "abstain"                       # 无依据断言过多：降级为仅提供原文
else:
    decision = "accept"
print(f"\n断言 {total} 条，无引用 {uncited} 条，引文不符 {bad_quote} 条，未知来源 {unknown} 条")
print(f"决策：{decision}")
```

预期输出（本机 `python3` 实跑一致）：

```text
[通过] S2 生鲜商品不支持无理由退货【S…
[通过] S1 签收后 7 日内未拆封可以申…
[引文不符] S1 引文不在原文中：退款将在 1 个工作日内到账
[无引用] 如有疑问请联系客服

断言 4 条，无引用 1 条，引文不符 1 条，未知来源 0 条
决策：reject
```

第三条断言最值得讲：它不是“编造来源”，而是引用了正确来源却改了数字。这类错误很难靠模型自检发现，只能靠引文逐字比对。“如有疑问请联系客服”没有引用，属于可容忍的非事实话术，所以用比例而非绝对值判断。

## 动手实验

前置条件：Python 3.9+，无需第三方包。把上一节代码保存为 `citation_gate.py`。

步骤：

1. 运行一次，确认输出与上文一致，决策为 `reject`。
2. 把第三条断言的引文改成 `SOURCES` 中真实存在的句子，重新运行，观察决策变化。
3. 删掉最后一条无引用断言，观察无引用比例如何影响 `abstain` 阈值。
4. 把阈值从 `0.2` 改为 `0`，体验“零容忍”策略。

预期结果：第 2 步后硬错误消失，决策变为 `accept`；第 3 步后无引用比例从 0.25 降到 0，阈值再高也能通过；第 4 步只有纯引用回答能通过。

验证方法：手工核算“通过条数 ÷ 断言总数”，与脚本统计核对；再把一条引文改成只差一个数字，确认仍判为不符——这验证的是逐字比对，而不是模糊相似。

清理方法：删除 `citation_gate.py`，或将它移入 `tests/` 作为回归用例。本实验不发起网络请求，不产生费用。

## 常见错误与排查

| 现象 | 可能原因 | 验证方法 | 修复方向 |
| --- | --- | --- | --- |
| 引用编号整体错位 | 用数组下标当引用号，重排后失效 | 对比重排前后的编号映射 | 改用稳定 ID（文档+版本+切片） |
| 引文正确但结论相反 | 只校验“是否存在”，未校验“是否支持” | 人工抽 50 条比对引用与断言语义 | 增加支撑判断（规则或模型判定） |
| 每条回答都有引用，质检仍不过 | 引用只到文档级，读者无法定位 | 抽查能否在 10 秒内找到原句 | 提升到条款/句子级并附原文 |
| 检索为空却仍在回答 | 缺少无依据拒答分支 | 构造空检索用例回放 | 增加 abstain 前置判断 |
| 引用的是旧版政策 | 来源元数据没有生效日期 | 检查切片元数据字段 | 带版本与生效日期，并做过期校验 |

## 安全与生产注意事项

**<u>模型生成的引用编号、引文和链接必须视为不可信输入，渲染成可点击链接前必须由服务端校验并重建。</u>** 否则被投毒的知识库文档可以诱导助手输出指向钓鱼站点的“官方链接”，用户点开就离开了你的信任边界。

**<u>引用不能替代权限校验。</u>** 一条引用合法只说明来源存在，不说明提问者有权看到它；把无权文档的标题或摘要渲染进引用卡片，同样构成越权披露。

另外两条工程要求：审计日志应保存本次检索的切片 ID 与模型版本，否则三个月后无法复现；拒答不是失败，应单独统计“合理拒答率”，避免团队为指标好看而鼓励硬答。

## 本课总结

- 引用是标记，溯源是可复核链路；能回到具体原文与版本，回答才可审计。
- 粒度由错误代价决定，金额、时效、责任类断言应细化到条款或句子级。
- 可信回答的关键不在提示词，而在服务端的逐字校验与覆盖度阈值。
- 引文正确但结论被改写，比“编造来源”更隐蔽，也更常见。
- 拒答是可设计、可度量的产品行为，应显式建模。

## 思考题

客服主管提出：“既然引用老出错，干脆让模型只输出原文，不做总结。”请分析这个方案的收益、代价与适用边界，并说明在什么条件下你会接受它。

参考思路：收益是可溯源性和合规性最大化，代价是回答冗长、术语密集、客户体验下降，且无法跨文档比较与归纳。可以按风险分层：费率、法务、赔付走抽取式，咨询类走“总结 + 引用”。还要评估客服阅读成本与客户转化，不能只看质检通过率。

## 小测

1. 引用与溯源的区别是什么？
2. 下列哪种断言最需要句子级引用？  
   A. 商品简介　B. 退款到账时效　C. 品牌故事　D. 使用建议
3. 为什么引用校验要做“逐字子串比对”而不是“语义相似度”？
4. 回答中 30% 的断言没有引用，按本课策略应如何处置？
5. 场景题：检索只返回《通用退货规则》，没有返回《生鲜类目规则》，模型仍给出“生鲜支持 7 天无理由”。请指出至少两个失效环节与修复方向。

## 答案与解析

1. 引用是回答中指向来源的标记，用户可见；溯源是可被机器复核的完整链路（来源 ID、版本、位置、原文）。只有引用没有溯源，等于给了无法核对的出处。
2. **B。** 时效直接影响赔付承诺，必须定位到条款原句。A、C、D 属于描述性或建议性内容，文档级引用通常足够。
3. 语义相似度区分不了“引用了正确来源”和“引用了正确来源但改了关键数字”。示例中“1 个工作日”与“3 个工作日”语义高度相似，只有逐字比对能拦住。
4. 超过 20% 阈值，应降级为 `abstain`：只提供原文片段或明确说明依据不足，并转人工，而不是照常输出。
5. 失效点一：检索未命中类目规则，系统没有“低分或空结果”的兜底判断，应增加拒答分支。失效点二：生成阶段允许模型使用参数知识而非仅用上下文，应收紧 Prompt 并在服务端校验引用是否来自本次检索结果。
