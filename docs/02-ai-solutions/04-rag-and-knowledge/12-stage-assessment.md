# RAG 阶段综合测评

## 学习目标

本测评检查你能否把十一课的内容合成一条自洽的检索链路，而不是复述术语。建议闭卷完成概念题，再开卷做场景与交付物，最后用评分表自评。允许答案不同，但每个数字、阈值和决定都要说明依据。

## 知识检查清单

- [ ] 能解释 embedding、维度与距离度量的关系，并说明阈值为何必须与度量绑定。
- [ ] 能说明 ANN 索引的召回损失，并为 `ef_search` 给出有依据的取值。
- [ ] 能为多格式知识源设计解析、清洗与元数据，且知道哪些丢失是静默的。
- [ ] 能在原子单元边界切分，并用标题前缀与重叠保留前提。
- [ ] 能说明 BM25 与向量检索各自的失效场景，并用 RRF 融合。
- [ ] 能判断何时需要 rerank，并设计绝对阈值、相对阈值与去重规则。
- [ ] 能写出引用契约，并用逐字校验决定回答、降级或拒答。
- [ ] 能设计“先过滤后召回”的权限模型，并识别后置裁剪的越权路径。
- [ ] 能用内容指纹与切片 ID 设计可重跑的增量同步和删除传播。
- [ ] 能把 RAG 效果拆成检索层与生成层指标，并按固定顺序归因。
- [ ] 能在向量检索、Graph RAG、长上下文与微调之间按约束取舍。

## 概念题

四选一每题 2 分，简答每题 4 分，共 40 分。

1. 两段文本的向量都已做 L2 归一化，此时内积与余弦相似度的关系是（　）
   - A. 内积恒大于余弦
   - B. 两者数值相等
   - C. 两者方向相反
   - D. 无法比较

2. 在 HNSW 索引上调大 `ef_search`，通常的直接后果是（　）
   - A. 召回提升、延迟上升
   - B. 召回下降、延迟下降
   - C. 内存占用归零
   - D. 距离度量自动改变

3. 把带行列结构的 PDF 表格直接按字符流向量化，最典型的故障是（　）
   - A. 向量维度溢出
   - B. 表头与数值分离，片段失去语义
   - C. 索引不再支持过滤
   - D. 余弦相似度失效

4. 片段中出现“已激活或已使用的商品不适用七天无理由”，却漏掉上一句“本政策仅适用于自营商品”，根因是（　）
   - A. embedding 模型太小
   - B. 切分切断了原子单元，且片段缺少标题前缀
   - C. 索引使用了 IVF
   - D. rerank 模型未加载

5. 客户问“QC-2026-BLK 的电池保修多久”，纯向量召回返回一堆泛泛保修条款，首选修法是（　）
   - A. 把 top-k 调大到 200
   - B. 增加 BM25 关键词通道做混合召回
   - C. 换更小的 embedding 维度
   - D. 关掉 rerank

6. 混合检索后正确条款排第 3，第 1 名是“运费承担”，最合适的下一步是（　）
   - A. 直接取前 60 条塞进上下文
   - B. 对候选集做 cross-encoder rerank
   - C. 提高 RRF 的 `rank_constant` 到 600
   - D. 把向量库换成图数据库

7. 回答带了一个链接，点开是讲通用退货规则的旧公告，这说明缺的是（　）
   - A. 更长的上下文窗口
   - B. 引用契约与版本校验：引用必须指向生效版本的具体原文
   - C. 更低的 temperature
   - D. 更多的少样本示例

8. 先取 top-10 再用应用层代码过滤无权文档，主要问题是（　）
   - A. 越权文档仍参与排序，挤占名额，且可能经日志或缓存泄露
   - B. 只会让延迟翻倍
   - C. 只会影响多租户成本
   - D. 没有影响，过滤后模型看不到

9. 政策当天改了有效期，助手两周后仍答旧值，最可能的缺口是（　）
   - A. Prompt 措辞不够强
   - B. 没有增量同步与内容指纹，索引仍是一次性快照
   - C. rerank 阈值过严
   - D. 向量维度不够

10. 产品经理挑的 8 道题全对，上线后客服说“一半不相关”，直接原因是（　）
    - A. 模型能力不足
    - B. 缺少覆盖检索层与生成层的分层评测集与归因表
    - C. 索引类型选错
    - D. 引用格式不规范

11. 为什么“相似度高”不等于“答案正确”？阈值应该在哪里标定？

12. 分别给出一句话，说明长上下文、Graph RAG、微调各自解决什么、各自的一个失效条件。

13. 为什么说融合只能保证好候选进入候选池，最终顺序仍要 rerank 决定？

14. 引用校验为什么必须在服务端做逐字比对，而不是让模型自己在答案里标来源？

15. 列举三个会静默丢数据的环节，并各给一个能发现它的观测指标。

### 常见错答分析

| 题目 | 常见错答 | 为什么不充分 | 纠正方向 |
| --- | --- | --- | --- |
| 1、2 | 认为调参只影响速度，或把内积与余弦当成两种无关度量 | 归一化后两者数值一致；`ef_search` 是召回与延迟的交换旋钮 | 把度量、阈值、索引参数绑在同一张表里 |
| 3、4 | 认为解析失败会报错，或切分只影响长度 | 表格错位、前提被切断都不报错，只表现为答非所问 | 用空文本率、表头还原率、命中但答案残缺率监控 |
| 5、6 | 靠无限放大 top-k 掩盖召回缺陷 | 名额被无关片段占满，反而拖低精度并推高成本 | 补关键词通道，再用 rerank 收窄候选 |
| 7、8 | 把引用当成排版问题，把权限当成结果过滤 | 旧版本引用与后置裁剪都会造成“看起来对、实际越权或过期” | 引用绑版本与原文，权限在召回前裁剪 |
| 9、10 | 出了偏差先改 Prompt，或只用演示题衡量效果 | 数据陈旧和评测缺失都不是生成层问题 | 建立对账与回归门禁，再谈提示词优化 |

## 场景分析

**本测评刻意换场景，检验迁移。** 下面的公司与数据均与晴空商城不同。

瀚川精密（虚构）为工业磨床提供售后服务：现场工程师到客户车间维修，随身只有平板，需要边拆边查。知识源四类——3000 页 PDF 维修手册（含大量故障代码表与扭矩参数表）、按渠道分级的保修条款、40 万条历史工单（含客户名与报价）、季度改版公告。工程师的提问很口语：“E-4021 报警，主轴异响，先查哪？”

请回答五个小问，各 6 分：

1. 为这句提问设计召回链路：需要哪几路、为什么单靠向量不够；说明你如何为“E-4021”这类标识符留出通路。（对应：[05-hybrid-search-and-query-rewriting](05-hybrid-search-and-query-rewriting.md)）
2. 扭矩参数表应当怎么切分、带什么元数据，才能让工程师看到数值时知道它属于哪台机型、哪道工序。（对应：[03-document-ingestion-and-metadata](03-document-ingestion-and-metadata.md)、[04-chunking-and-context-preservation](04-chunking-and-context-preservation.md)）
3. 一级经销商只能看基础手册，二级经销商不能看扭矩公差页。写出你的权限裁剪位置与允许的过滤字段来源。（对应：[08-permission-aware-retrieval](08-permission-aware-retrieval.md)）
4. 手册每季度改版，旧扭矩值必须当天下线。给出同步、删除与回归验证的组合方案。（对应：[09-incremental-indexing-and-sync](09-incremental-indexing-and-sync.md)、[10-rag-evaluation-and-error-analysis](10-rag-evaluation-and-error-analysis.md)）
5. 工程师问“这台 2016 年的旧机型保修多久”，该机型已停产、条款不在库内。写出系统应有的行为链路。（对应：[06-rerank-and-context-assembly](06-rerank-and-context-assembly.md)、[07-citations-and-grounded-answers](07-citations-and-grounded-answers.md)）

## 架构师交付物练习

为上述场景写一页“检索服务设计卡”（30 分）。建议结构：

1. **目标与失败定义**：一句话说明检索要支撑什么任务；列出你判定为失败的三类结果。
2. **知识与元数据**：四类源各自的解析策略、必填元数据字段（机型、章节、生效区间、可见级别、文档版本）。
3. **切分与索引**：原子单元是什么、前缀怎么写、用哪种索引与度量，并给一个参数取值和理由。
4. **召回与排序**：几路召回、融合方式、rerank 触发条件、阈值与上下文预算。
5. **安全与生命周期**：权限裁剪点、删除传播路径、对账频率。
6. **证据与评测**：引用粒度、拒答条件、检索层与生成层各两个指标。
7. **开放问题**：写三条你还需要谁确认的事，不要用假设补全。

不需要画部署图，也不要给未经测量的收益数字。

## 参考答案与解析

### 概念题答案

1. **B**。归一化后向量长度为 1，内积等于余弦；阈值必须与所用度量一致，换度量等于换了一把尺子。
2. **A**。`ef_search` 扩大候选队列，召回上升、延迟上升；它是交换参数，不是“越大越好”的开关。
3. **B**。表格的语义在行列关系里，按字符流切会把表头与数值拆散，片段既无单位也无适用条件，且不报错。
4. **B**。切分切断了“适用自营商品”这个前提，片段又无标题前缀，模型看到的是一句被放大范围的规则。
5. **B**。型号是无意义字符串，embedding 会把它抹平成“某商品”；必须有 BM25 通道兜住标识符，再融合。
6. **B**。RRF 只保证候选，排序要靠 cross-encoder 看 query 与片段的相关性；调 `rank_constant` 是次要手段。
7. **B**。有链接不等于可溯源；引用必须绑定生效版本与具体原文，否则旧公告会被当成现行依据。
8. **A**。后置裁剪既让越权文档参与排序、挤占名额，又会经日志、缓存、链路追踪泄露内容。
9. **B**。一次性导入的索引不会自己更新；内容指纹负责判断变更，版本化切片负责让旧切片被显式删除。
10. **B**。8 道题是演示集不是评测集；没有分层指标就无法区分检索没召回还是生成不忠实。
11. 相似度衡量的是表达接近，不是事实正确：近义表述、过期版本、相反结论都可能高分。阈值应在自己的标注集上按业务代价标定，并同时保留绝对阈值与相对阈值。
12. 长上下文解决“放不下”，不解决“找得准”和“查得到权限”；Graph RAG 解决多跳关系，代价是索引期高成本与更新困难；微调擅长风格格式，不擅长承载高频变化的事实。
13. 融合按名次而非分数合并，能让好候选不被单路埋没，但两路都没错也不代表对这条问题最相关；精度需要 cross-encoder 在候选集上重排。
14. 模型自标来源会“引用装饰”：引文正确而结论被改写，或指向不存在/过期段落，外部无法复核。服务端逐字比对加覆盖度阈值，才能把不可信的回答降级或拒答。
15. 例：扫描版 PDF 解析出空文本——空文本率；表格错位——表头还原率；切分切断前提——命中但答案残缺率；删除未传播——索引与源数据条数对账差。

### 场景分析参考思路

1. **召回**：向量通道处理“主轴异响”这类口语描述，BM25 通道处理“E-4021”；两路用 RRF 融合，`rank_constant` 取 60 左右。标识符还要在入库时保留原样，不被清洗规则吃掉。
2. **表格**：以“机型+工序+参数行”为原子单元，标题前缀写机型与章节号；元数据含机型、手册版本、生效季度、页码，引用可回到具体表行。
3. **权限**：在召回前用服务端构造的过滤表达式裁剪（按渠道级别与文档可见级别），客户端传来的身份字段一律忽略；索引中的 ACL 视为权限源副本，需监控同步延迟。
4. **同步**：改版触发指纹变化 → 新切片入库、旧版本切片按 ID 显式删除；保留生效区间用于回溯；回归集固定一批扭矩类问题，改版后必须重跑并过门禁。
5. **无答案**：先经 rerank 与绝对/相对阈值筛掉弱证据；证据不足则拒答并给出升级路径（联系区域技术支持、查停产机型迁移表），不输出猜测参数，也不引用无关旧公告。

常见错误：把标识符交给 embedding 硬扛；表格按固定字数切；权限写在结果过滤里；改版只做新增不做删除；无答案时让模型“尽力回答”。

### 交付物参考结构

| 部分 | 参考内容 |
| --- | --- |
| 目标与失败 | 支撑现场排障；失败=无召回、引用过期、越权可见、编造参数。 |
| 知识与元数据 | 手册走结构化解析，工单走清洗去报价；元数据含机型/章节/版本/生效区间/可见级别。 |
| 切分与索引 | 原子单元=故障代码条目、工序参数行；HNSW+余弦，`ef_search` 给出取值与实测召回。 |
| 召回与排序 | 向量+BM25+RRF，rerank 于 top-40，绝对与相对阈值各一条，上下文预算按条数。 |
| 安全与生命周期 | 召回前裁剪 ACL；硬删+软删+TTL；每日对账条数与抽样内容。 |
| 证据与评测 | 引用到表行；覆盖度不足即拒答；检索看 recall@k，生成看引用支撑率。 |
| 开放问题 | 停产机型条款归属、二级经销商诉求边界、改版发布窗口。 |
