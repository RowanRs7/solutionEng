# 切分、重叠与上下文保留

## 为什么需要学习

晴空商城的退货政策原文只有 8 页，但入库时必须切成几百个片段，因为检索和生成都受长度限制：一个向量只能代表一段相对集中的语义，模型上下文也要留给多个候选。切分方式一变，检索结果就跟着变。

第一版按“每 500 字切一刀”处理，结果两个方向都翻车。切得太碎时，模型拿到“已激活或已使用的商品不适用七天无理由退货”，却看不到上一句“本政策仅适用于自营商品”，于是对第三方商家的订单给出了错误结论。切得太大时，一个片段里同时塞了退货、运费、发票三种规则，向量被平均成“什么都像一点”，客服问运费反而命中退货条款。

> **核心结论：** 片段是检索的最小单位，也是模型唯一能看到的事实；切分决定“能不能找到”，上下文保留决定“找到了能不能用”。

## 学习目标

完成本课后，你能够：

- 判断一段内容应以条款、问答对还是表格行为切分单元，并说明理由。
- 用标题前缀、父子块或重叠三种手段之一修复“片段脱离原文后含义丢失”。
- 解释重叠为什么会在 top-k 中制造重复，并给出可验证的重叠比例。
- 用片段长度分布与命中样例定位切分问题。

- 知道 embedding 模型有单次输入上限，且一个向量只能表达一段相对集中的语义。

## 业务场景

售后知识库有三类内容，切分诉求各不相同：政策条款（层级清晰、一条一款，必须成条完整）、FAQ（问与答必须成对）、运费时效表（每行都要带表头）。客服提问往往是口语化的一句话，需要片段既能独立读懂，又能精确对应到“第几条”。

晴空商城的目标是：任一片段脱离原文单独阅读时，读者都能知道它出自哪份政策的哪一条、适用于谁、有没有例外。

## 核心概念

*片段（chunk）* 是入库、向量化与检索的最小文本单元。*切分策略* 决定边界如何确定；*重叠（overlap）* 是相邻片段共享的尾部文本；*上下文前缀* 是在片段正文前补上标题路径；*父子块* 是索引小片段、返回大片段的两级结构；*原子单元* 是不可再分的语义整体，例如一条完整条款、一组问答。

| 策略 | 边界依据 | 适用 | 主要风险 |
| --- | --- | --- | --- |
| 固定长度切分 | 字符或 token 数 | 无结构的纯文本、日志 | 切断句子与条款，边界随机 |
| 段落/换行切分 | 空行与换行 | 结构良好的说明文档 | 段落极长时仍需二次切分 |
| 结构切分 | 标题层级（h1–h3） | 政策、手册、规范 | 单条过长时要再按句子切 |
| 语义切分 | 相邻句子向量相似度突变 | 长文、访谈稿 | 成本高、边界不稳定 |
| 父子块 | 检索用小片段，返回用父块 | 长条款需要完整上下文 | 存储与实现复杂度上升 |

尺寸与重叠的取舍没有通用数字，只有约束下的选择：

| 片段规模 | 检索效果 | 生成效果 | 适用 |
| --- | --- | --- | --- |
| 很小（约 100–200 token） | 语义集中、命中精确 | 常缺前提与例外，易答非所问 | 原子条款、FAQ 单条 |
| 中等（约 300–600 token） | 平衡 | 多数场景可独立阅读 | 政策条款、说明书段落 |
| 很大（约 1000 token 以上） | 一向量混多主题，区分度下降 | 上下文充足但噪声多、成本高 | 需要整章推理的技术文档 |

## 工作原理

1. **识别原子单元**：先按文档结构找到最小不可分单元——条款、问答对、表格行。切分只能在单元之间发生，不能在单元内部发生。
2. **设定目标与硬上限**：目标长度用于控制检索粒度，硬上限来自 embedding 模型的输入上限（常见 8192 token），两者都要写进配置。
3. **递归切分**：优先按标题切，其次按段落，再按句子，最后才按固定长度兜底。**顺序不能颠倒**，否则结构信息会在第一步就丢失。
4. **补上下文前缀**：把“文档标题 > 条款标题”拼在正文前，使片段脱离原文仍可理解；前缀同时提高 BM25 对标题词的命中。
5. **加重叠**：在相邻片段间保留末尾若干句，避免边界处的条件被切断；重叠要按句子取整，不能按字符硬切。
6. **处理特殊类型**：表格每行重复表头后成文；FAQ 保持问答同块；代码块整块保留。
7. **记录定位信息**：保存 `doc_id`、`section`、`start_offset`、`end_offset`，供答案引用与人工核对。
8. **检查分布**：统计片段长度直方图与重复率，过长、过短、重复率高的文档回流人工调整。

第 5 步与第 4 步解决的是同一类问题：**片段必须自带解释自己所需的上下文**，只是手段不同。

## 架构与选型

| 方案 | 适用 | 不适用 | 权衡 |
| --- | --- | --- | --- |
| 结构切分 + 标题前缀 | 政策、规范、手册 | 无标题的会议记录 | 实现简单、可解释；依赖解析质量 |
| 固定长度 + 大重叠 | 快速原型、结构混乱的文本 | 条款型法规 | 上手快；重复多、边界不可控 |
| 父子块（小检大取） | 长条款需要完整上下文 | 存储与延迟敏感 | 召回精确且上下文完整；存储成本上升 |
| 语义切分 | 长篇叙述、访谈 | 条款清晰的结构化文档 | 边界更贴合语义；需额外模型调用 |

选型依据：**内容有没有结构**（有就先按结构切）、**回答需不需要完整条款**（需要就上父子块）、**延迟预算是否吃得下额外模型调用**（吃不下就别用语义切分）。

## 最小示例

下面的脚本用 Python 3 标准库实现“结构切分 + 标题前缀 + 句级重叠”，可以直接观察重叠带来的重复。

```python
import re

DOC = {
    "title": "晴空商城七天无理由退货政策",
    "sections": [
        ("第二条 适用范围",
         "本政策适用于晴空商城自营商品。已激活或已使用的电子产品不适用七天无理由退货。"
         "定制类商品一经生产即不适用本政策。赠品随主商品一并退回。"),
        ("第三条 运费承担",
         "因质量问题退货，运费由商城承担。非质量原因退货，运费由消费者承担。"
         "偏远地区退货运费按实际发生额结算，最高不超过订单金额的百分之十。"),
    ],
}

TARGET = 60     # 目标片段长度（字符）。生产环境应按 token 计，并留出前缀余量
OVERLAP = 1     # 每块携带上一块末尾的句子数，用于避免边界切断条件

def sentences(text):
    # 按中文句末标点切句并保留标点，避免句子被截断
    return [s for s in re.split(r"(?<=[。！？；])", text) if s.strip()]

def split_section(heading, body, target=TARGET, overlap=OVERLAP):
    chunks, cur = [], []
    for s in sentences(body):
        # 超过目标长度就先落块，再以尾部句子作为下一块的开头
        if cur and len("".join(cur)) + len(s) > target:
            chunks.append(cur)
            cur = cur[-overlap:] if overlap else []
        cur.append(s)
    if cur:
        chunks.append(cur)
    # 标题作为前缀拼回，保证片段脱离原文也能看懂
    return [f"{heading}｜{''.join(c)}" for c in chunks]

out = []
for heading, body in DOC["sections"]:
    for i, text in enumerate(split_section(heading, body)):
        out.append({"chunk_id": f"{heading[:3]}-{i}", "text": text, "chars": len(text)})

for c in out:
    print(c["chunk_id"], c["chars"], c["text"])
```

预期输出（已用 `python3 chunk_demo.py` 实际运行）：

```text
第二条-0 64 第二条 适用范围｜本政策适用于晴空商城自营商品。已激活或已使用的电子产品不适用七天无理由退货。定制类商品一经生产即不适用本政策。
第二条-1 37 第二条 适用范围｜定制类商品一经生产即不适用本政策。赠品随主商品一并退回。
第三条-0 42 第三条 运费承担｜因质量问题退货，运费由商城承担。非质量原因退货，运费由消费者承担。
第三条-1 58 第三条 运费承担｜非质量原因退货，运费由消费者承担。偏远地区退货运费按实际发生额结算，最高不超过订单金额的百分之十。
```

两个可观察现象。第一，每块都带“第二条 适用范围”前缀，单独阅读仍知道出处。第二，“定制类商品……”与“非质量原因退货……”**同时出现在相邻两个片段里**——这正是重叠的代价。<u>当 top-8 里有 2 条是同一段话的重复时，实际有效上下文只剩 7 条甚至更少。</u>

片段长度也不均匀（37 到 64 字符）：因为按句切分不能打断句子。**这是可接受的取舍，但必须在入库时统计长度分布**，否则超长片段会悄悄稀释向量。

## 动手实验

**前置条件**：Python 3.9+，无需网络。

1. 保存脚本为 `chunk_demo.py`，运行并记录片段数与长度。
2. 把 `TARGET` 改为 30，观察片段数增加、每块仍带前缀，以及重叠是否让重复更明显。
3. 把 `OVERLAP` 改为 0，重跑，统计“定制类商品”出现在几个片段里。
4. 去掉 `f"{heading}｜"` 前缀，只保留正文，阅读切出的片段，判断是否还能独立理解。
5. 删除脚本。

**预期结果**：`TARGET=30` 时片段数明显增多且单块信息变少；`OVERLAP=0` 时重复消失，但“定制类商品”与上一句的因果关系可能被切断。去掉前缀后，片段失去条款归属信息。

**验证方法**：统计“片段总数 / 原始句子数”的比值，比值远大于 1 说明切得过碎；随机抽 10 条片段遮住原文单独阅读，若读不懂就说明上下文保留不足。

**清理方法**：删除 `chunk_demo.py`；不写数据库、不产生费用。

## 常见错误与排查

| 现象 | 可能原因 | 验证方法 | 修复方向 |
| --- | --- | --- | --- |
| 检索命中但回答缺前提 | 片段切断了限定条件或标题 | 打印命中片段全文，看是否含“仅适用于”等限定句 | 结构切分 + 标题前缀，必要时用父子块 |
| top-k 里多条内容雷同 | 重叠过大，重复片段挤占名额 | 统计 top-8 中正文重合度 | 重叠降到 10%–15%，或按句取整后去重 |
| 运费数字与区域错配 | 表格按字符切分，表头与数据行分离 | 检查片段是否带表头字段 | 每行重复表头，禁止跨行切分 |
| 问答只剩答案没有问句 | FAQ 被按段落切开 | 抽查 FAQ 片段的开头 | 问答对作为原子单元，整对入库 |
| 片段长度差异极大 | 按句切分遇到超长合同句 | 画长度分布直方图 | 设硬上限，超长句再按分号或从句切 |
| 换了切分参数后召回全线下降 | 切分与索引、评测集同时变更，无法归因 | 固定评测集，单变量对比 | 参数变更走实验记录，先离线评测再上线 |

## 安全与生产注意事项

**<u>固定长度切分会把受限内容与公开内容混进同一片段，导致权限判断失效：片段被判定为公开，其中却包含内部赔付口径。</u>**切分边界必须尊重文档的权限边界，片段 ACL 取覆盖范围内最严格的级别，并写进元数据。

**<u>片段是模型的“事实来源”，因此也是注入入口：不可信文档中插入的“忽略以上规则”会随片段进入上下文。</u>**切分阶段就要标记来源可信度，生成阶段对片段内容做隔离引用，不让片段文字被解释为系统指令。

另一点容易忽略：删除文档后如果只删原文件、不删片段，旧片段仍会被检索并按“最新政策”口吻回答；片段的生命周期必须跟随源文档，删除、失效、替代都要联动。

## 本课总结

- **切分只能在原子单元之间发生，不能在单元内部发生。**
- 结构切分优先于固定长度切分；标题前缀让片段自带出处与适用范围。
- 重叠用于避免边界切断条件，代价是 top-k 名额被重复内容占用。
- 片段太大稀释语义，太小丢前提；长度分布必须监控。
- 表格、FAQ 需要专门规则，通用切分器无法自动处理。

## 思考题

晴空商城想把“退款审核口径”这类超长文档（单条 2000 字以上）纳入知识库，客服既需要精确找到某一句，也需要模型看到完整条款才能判断例外。请比较“单一大片段”和“父子块”两种方案在检索精度、上下文成本、实现复杂度上的差别，并说明你会用哪些指标判断方案是否奏效。

参考思路：单一大片段实现简单，但向量被多主题稀释、检索精度下降，且每命中一次就消耗大量 token；父子块用小片段精确检索、按需返回父块，精度与上下文兼顾，但需要额外存储与一层查表。判定指标可看“命中片段是否包含正确条款句”的精确率与“每次回答的上下文 token 数”。

## 小测

1. 为什么切分参数变化会让检索“突然变差”，而代码并没有 bug？
2. 下列哪种做法最能保留片段的自解释性？  
   A. 把片段长度固定为 200 字　B. 在每个片段前拼接标题路径　C. 增大重叠到 50%　D. 删除所有标点
3. 重叠（overlap）解决什么问题，又带来什么副作用？
4. 表格类内容为什么不能按通用规则切分？
5. 场景题：客服问“赠品需要一起退回吗”，系统返回的片段是“赠品随主商品一并退回。”——答案正确，但模型回答时又说“请联系人工确认”。你怀疑什么？

## 答案与解析

1. 因为检索质量依赖片段边界：边界变了，片段所代表的语义就变了，向量与 BM25 打分随之变化。参数属于产品决策而非代码逻辑，所以“没有 bug 也会变差”。
2. **B。**标题路径提供出处与适用范围，使片段脱离原文仍可理解。A 固定长度只会更随机地切断句子；C 增大重叠制造重复并挤占 top-k；D 删除标点破坏句子边界与语义。
3. 它避免把限定条件切在片段边界外，让相邻片段共享过渡句。副作用是同一句话进入多个片段，造成 top-k 重复、浪费上下文预算，并使“命中条数”虚高。
4. 因为表格的语义存在于行列关系中：单个单元格没有意义，而通用切分会按字符切断行与表头的对应关系，导致“12 元”失去“首重、华南”等限定。
5. 很可能命中的片段过短，缺少“退货政策适用范围”和“赠品定义”这两个前提，模型因此不敢下结论而转向保守话术；也可能是片段没有带条款标题，模型无法引用出处。验证方法是打印该片段的完整内容与元数据，检查是否含标题前缀与相邻条件句。
