# 部署、运行与优化

## 单元目标

前一个单元解决"这套 AI 方案该不该上线"；本单元解决"上线之后它能不能撑住、算得清、查得到、退得回"。

完成本单元后，你能把一次线上运行拆成四类可回答的问题：请求走哪条路径、资源够不够、每一分钱花在哪、凭什么证据下判断。四者互相咬合——没有容量估算就没有可信的延迟承诺，没有成本归因就无法判断优化是否值得做，没有 trace 就只能靠猜。你不必成为 GPU 运维工程师，但要在评审会上对"要不要自建""峰值会不会崩""这次改动敢不敢发"给出有依据的回答。

## 学习路线

预计 **7–9 小时**。课程按顺序学习，后一课默认你已完成前一课练习：

1. [托管 API、自建推理与混合部署](01-hosted-api-self-hosted-and-hybrid.md)：三种部署形态的交易结构，以及为什么路由规则才是选型交付物。
2. [GPU、推理端点与容量](02-gpu-endpoints-and-capacity.md)：KV Cache 决定并发上限，副本数由峰值 QPS 与单副本能力推出。
3. [并发、吞吐、首 Token 延迟与总延迟](03-concurrency-throughput-and-latency.md)：延迟的四段拆解、Little 定律与 goodput。
4. [Token 用量、预算与成本控制](04-token-cost-and-budget.md)：把账单拆成输入、缓存与输出，并配上告警、降级、熔断三层护栏。
5. [AI Trace 与端到端可观测性](05-ai-tracing-and-observability.md)：用 span 与自耗时回答"模型看到了什么、做了什么"。
6. [Prompt、检索、模型与工具的故障定位](06-troubleshooting-prompt-retrieval-model-tools.md)：先定位层，再定位因，避免把假修复当成果。
7. [灰度、回滚、迁移与持续评测](07-gray-release-rollback-and-continuous-eval.md)：版本三元组、确定性分桶、守卫阈值与回归集。
8. [供应商限流、模型退化与 AI Runbook](08-provider-limits-model-drift-and-runbook.md)：四类外部事件的差异化处置，以及可演练的处置手册。
9. [AI 运维阶段综合测评](09-stage-assessment.md)：覆盖全部八课的综合测评。

## 贯穿场景

晴空商城的售后智能助手在本单元被从另一个侧面观察：它已上线三个月，功能验收早已通过，但合规评审指出检索订单时会把收件人手机号、地址和退款凭证一起送出境外的托管 API；大促期间托管侧频繁返回 `429`，客服页面出现数十秒空白；成本在请求量只涨两成的情况下翻了三倍；一次"优先引用最新政策"的提示词微调让投诉量上升四成，而团队发现只能回滚代码，回滚不了 Prompt、索引与模型版本的组合。

这八课不是八份独立清单，而是同一系统在不同压力下的八个切面：合规与成本逼出路由，路由逼出容量，容量与延迟共用指标口径，指标与 trace 支撑排障，排障结论又决定发布策略与 Runbook。

## 必交成果

- 一份路由规则表：判定输入、判定顺序、未知标签处理方式与责任人。
- 一份容量估算：单副本并发上限、峰值并发需求与副本数安全系数。
- 一套延迟指标口径：TTFT、TPOT、端到端、尾延迟与 goodput 的定义和样本范围。
- 一张单工单成本表：按固定前缀、检索、历史、问题、输出分段，并配三层护栏阈值。
- 一份 trace 规范：span 结构、必填属性、脱敏规则与采样策略。
- 一组版本三元组与发布包：灰度粒度、守卫阈值、回滚点与一份演练过的 Runbook。

## 完成规则

先学完全部八课并完成课内练习，再做阶段测评。测评满分 100 分，**80 分及以上**视为掌握本单元；**60–79 分**按测评给出的复习路线回看对应课程并补做该部分练习，然后重测；**低于 60 分**应重新完成全部课程练习，重点检查容量、成本、可观测性三处是否只有结论而缺少数据来源。
