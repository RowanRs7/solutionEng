# 工具调用、Workflow 与 Agent

## 单元目标

前面几个单元，模型已经能读懂需求、会写提示词、能检索资料。但它仍然只会“说”——说得很像，却碰不到任何真实系统。

打个比方：这是一位口才极好、记性也不错的顾问，坐在会议室里给你出主意。可他既没有工位钥匙，也登不进订单系统，更不可能替你去财务签字。**你要解决的不是让他更会说话，而是让他能安全地“替你办事”。**

学完本单元，你能做三件事：

- 把业务流程拆成一个个**有契约的动作**（叫什么、要什么参数、返回什么、出错怎么办）；
- 把“下一步做什么”的决定权**从模型手里收回代码**，只在真正需要临场判断的地方交给 Agent；
- 给会动钱、动数据的动作配好**权限、审批和兜底**。

三条主线贯穿全单元：**契约**（描述、Schema、返回信封）、**权限与流程**（身份、对象、审批断点）、**可靠性**（超时、重试、幂等、审计）。它们对应三个不同的问题——模型知不知道怎么做、允不允许做、做砸了怎么办，缺一条都上不了生产。

## 学习路线

预计学习时间为 **7–9 小时**，按顺序学习效果最好；每个核心课都带一段可离线运行的代码，建议边读边敲。

1. [Function Calling 的工作机制](01-function-calling-mechanics.md)：四段循环、回填与终止条件，执行在应用侧。
2. [工具描述、参数 Schema 与返回值](02-tool-schemas-and-descriptions.md)：描述管选择，Schema 管填参，信封管下一步。
3. [工具权限、校验与最小授权](03-tool-permissions-and-least-privilege.md)：主体、操作、对象三元组与分级执行。
4. [Workflow 与 Agent 的区别](04-workflow-vs-agent.md)：按控制流归属与诉求分布选编排。
5. [状态机、分支、循环与人工审批](05-state-machines-branches-and-approval.md)：审批写成可恢复、可过期的状态机。
6. [Agent 的规划、执行与反思](06-agent-planning-execution-and-reflection.md)：用外部信号判断对错，而非模型自评。
7. [会话状态、短期记忆与长期记忆](07-session-and-memory.md)：分作用域、定写入策略、留删除能力。
8. [MCP、单 Agent 与多 Agent 的边界](08-mcp-and-single-vs-multi-agent.md)：标准化暴露方式，不转移责任。
9. [工具超时、重试、沙箱、审计与失败模式](09-tool-reliability-sandbox-and-failure-modes.md)：让失败可识别、可收敛、可复盘。
10. [工具与 Agent 阶段综合测评](10-stage-assessment.md)：换场景检验迁移，产出设计说明书。

**按时间挑读法：**

- 只有半小时：读本页 + [第 4 课](04-workflow-vs-agent.md)的“架构与选型”两张表，先建立“该不该上 Agent”的判断力。
- 有半天：读 [第 1 课](01-function-calling-mechanics.md)、[第 3 课](03-tool-permissions-and-least-privilege.md)、[第 9 课](09-tool-reliability-sandbox-and-failure-modes.md)，这三篇覆盖最容易出事故的地方（循环、越权、重复执行）。
- 准备做设计评审：按顺序全读，重点产出“必交成果”里的五张表。

## 贯穿场景

晴空商城售后助手在本单元被逐层拆开。客户说：“上周买的降噪耳机，左耳没声音，我要退款。”这句话背后是一条真实链路：查订单（只读）、检索售后政策（知识库）、判断符不符合退款条件、算能退多少、写答复，最后可能还要提交退款（动钱）。

课程从“模型只产出调用意图”讲起，逐课收紧契约、权限、编排、审批、记忆与外部接入。九课读完后，你要能回答客服小陈最后那个问题：“支付网关卡住的那笔退款，到底成功了没有？”—这个问题的答案不在模型的话里，而在状态记录、幂等键和对账记录里。

## 必交成果

五张表看着多，其实是同一件事的五个切面：先定义“能做什么”（契约），再定“谁能做”（权限），再定“按什么顺序做”（编排），再定“卡住了怎么办”（状态机与超时），最后定“出事了怎么查”（可靠性清单）。建议边学边填，每学完一课补一张，不要等到最后一次性补。

- 工具契约清单：读写属性、参数约束、返回信封与错误码。
- 权限与审批表：主体、操作、对象、判定依据、令牌绑定内容。
- 编排决策记录：诉求分布、选择依据、终止条件与步数预算。
- 状态机与超时去向表：状态、事件、守卫、超时后去向。
- 可靠性清单：分层超时、重试预算、幂等键、审计字段、已知失败模式。

## 完成规则

先学完九篇课程并完成课内小测与练习，再做阶段测评。测评满分 100 分：**80 分及以上**视为掌握；**60–79 分**按测评给出的复习路线回看对应课程，补完后重测一次；**低于 60 分**重做核心练习（工具契约、权限表、状态机）后再申请测评。提交成果时，未经确认的数字标“待测”并写明责任人与期限。

一个提醒：本单元的知识点不难，难在“想全”。很多事故不是因为方案错了，而是因为少想了一个方向——少写一个终止条件、少查一次对象归属、少留一个“结果未知”状态。做题时如果觉得“这也太细了”，先别删，问问自己：真出事时，这个字段能不能帮我定位到人。
